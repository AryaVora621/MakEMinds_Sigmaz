# field_sim architecture

FTC field simulator for the 2026-27 game BIOBUZZ. It loads a field model (CAD-exported or synthetic), exposes a headless numpy `Field` API, and renders it with PyVista. Physics, robot, and camera simulation are planned and must be able to reuse `sim.field` without any viewer dependency.

Status: the `sim/` package is being written against the API contract (`sim_contract.md`). Section 4 marks which hooks already exist in the contract and which are proposed additions.

## 1. Module map

| Module | Kind | Responsibility | Imports allowed |
|---|---|---|---|
| `sim/frames.py` | pure numpy | FTC <-> Pedro 2D/pose conversion, `FTC_TO_PEDRO_4x4`, angle wrapping | numpy, math |
| `sim/loader.py` | pure numpy | Model dataclasses (`Instance`, `Mesh`, `FieldModel`), `load_model`, `default_model_dir`, cache, `CATEGORIES`, `CATEGORY_PALETTE` | numpy, stdlib |

| `sim/field.py` | pure numpy (headless) | `Field`: hive state, world transforms, tags, aim points, zones, ball starts | numpy, loader, hive, frames |
| `sim/scene.py` | viewer | Builds PyVista scene: merged actor per (category, group), separate hive actors, LOD, `SceneHandles` | pyvista, field |
| `sim/overlays.py` | viewer | Tape zones, 144 outline, 24 in grid, axes, labels, tag normals, aim points, robot box | pyvista, field |

| `tools/make_synthetic_model.py` | offline tool | Writes `data/synthetic_model/` (boxes/spheres/cylinders with correct layout logic) | numpy, stdlib |
| `tests/` | pytest | Frame round-trips, hive identities, tag/aim geometry, headless-import check, CLI smoke render | pytest, sim |
| `docs/` | docs | This file, `QA_RENDERS.md`, `renders/` | n/a |

Data and cache directories:

- `data/field_model/`: real model from the extract pipeline (another team). Read-only for us. Considered ready only when `EXPORT_DONE.txt` exists. Its format is in `data/field_model/SCHEMA.md`.
- `data/synthetic_model/`: generated by `tools/make_synthetic_model.py`. Files: `model.json`, `parts.json`, `field_constants.json`, `tape_zones.json`, `ball_start_positions.json`, `meshes/<part>.npz`, `SCHEMA_SYNTHETIC.txt`.
- `data/cache/`: loader cache, gitignored. Never a source of truth.

## 2. Data flow

```
 extract pipeline (other team)          tools/make_synthetic_model.py
   writes data/field_model/               writes data/synthetic_model/
   (EXPORT_DONE.txt = ready)              (layout correct, geometry crude)
            \                                  /
             \                                /
              v                              v
        sim.loader.default_model_dir()  -- env FIELD_SIM_MODEL_DIR wins,
                       |                   else field_model if ready,
                       |                   else synthetic_model
                       v
        sim.loader.load_model(dir, use_cache)  --(cache: data/cache)-->
                       |
                       v
            FieldModel  (instances, parts, groups, constants,
                         tape_zones, ball_starts, get_mesh(key) lazy)
                       |
                       v
            Field(model)   headless, numpy only
            - hive_state {"red": "audience", "blue": "far"}
            - instance_transform(inst) -> world 4x4 incl. tip
            - tag_pose / aim_point / zone / ball_starts
                       |
          +------------+-------------------+
          v                                v
   sim.scene (pyvista)               future: physics, camera,
   sim.overlays (pyvista)            shooter, recorder (numpy only)
          |
          v
   run_sim.py  -> window, or --offscreen --out file.png
```

Model-dir precedence: `--model-dir` flag, then env `FIELD_SIM_MODEL_DIR`, then `data/field_model` if `EXPORT_DONE.txt` exists, then `data/synthetic_model`. Both `run_sim.py` and the tests accept the flag and the env var.

Loader tolerance: the real `field_constants.json` and `tape_zones.json` may differ from the synthetic layout. The loader normalises both into the same `FieldModel` fields and fails with a clear message on missing required keys rather than guessing.

Viewer/headless split rule: `sim.field` (and everything it imports: `frames`, `loader`, `hive`) must never import `pyvista`, `vtk`, or Qt. A future physics sim imports `sim.field` directly. Tests should enforce this by importing `sim.field` in a fresh interpreter and asserting that `pyvista` and `vtk` are absent from `sys.modules`.

## 3. Coordinate frames

### 3.1 Pedro frame (world, inches)

- Origin at the audience-left corner. +x right, +y toward the far wall, +z up.
- Field is 144 x 144 in. Red alliance at low x, blue at high x.
- All `Instance.transform` values, tag poses, aim points, zones and ball centres are in Pedro.
- Heading `h_p` is radians, wrapped to (-pi, pi].

### 3.2 FTC frame (game manual)

- Origin at the field centre. `x_f`, `y_f` on the floor, `h_f` heading.

### 3.3 Conversion

Field-centre offset is 72 in on each axis, plus a 90 degree rotation:

```
x_p = y_f + 72
y_p = 72 - x_f
h_p = h_f - pi/2        (wrap to (-pi, pi])

FTC_TO_PEDRO_4x4 = [[ 0, 1, 0, 72],
                    [-1, 0, 0, 72],
                    [ 0, 0, 1,  0],
                    [ 0, 0, 0,  1]]
```

The 2x2 part of this matrix has determinant +1 and equals a rotation by -90 degrees, which is why the heading shift is `-pi/2`. `pedro_to_ftc` is the exact inverse. Both are numpy-vectorised.

### 3.4 Part-local transforms

- `Instance.transform` is a 4x4 float64 matrix built from 16 floats stored row-major in `model.json`. It maps part-local coordinates to Pedro world: `p_world = M @ [p, 1]`.
- Mesh vertices are in part-local space. A world-space mesh is `(M[:3,:3] @ v.T).T + M[:3,3]`. Normals transform with `M[:3,:3]` only (rigid transforms, so no inverse-transpose is needed).
- Scene actors for hive groups are stored at CAD pose. When the tip changes, a delta is left-multiplied onto the instance matrix (section 4 explains the delta).

### 3.5 AprilTag frame columns

`tag_pose(id, tip_state)` returns a 4x4 whose columns are:

- column 0 (x): tag right, computed as `x = up x normal` so the frame is right-handed.
- column 1 (y): tag up (from `field_constants.tags[id].up`).
- column 2 (z): outward normal (from `tags[id].normal`), the direction the tag faces into the field.
- column 3 (translation): tag centre (from `tags[id].center`).

Tag `size_in` (3.25 in in the synthetic model) is the physical edge length. Corners in tag-local coordinates are at `(+-s/2, +-s/2, 0)`, which is the basis for the camera simulation in section 4.

## 4. Hive tip math

### 4.1 Geometry

Each alliance has a hive group `g` (`hive_red` or `hive_blue`). `model.json.groups[g]` contains:

- `pivot`: point on the tilt axis (Pedro inches). Synthetic: red `[59.25, 72, 43.95]`, blue `[84.75, 72, 43.95]`.
- `axis`: unit vector along the tilt axis. Synthetic: `[1, 0, 0]` for both.
- `cad_pose_angle_deg`: the angle the exported geometry is already at. Red -30, blue +30.
- `stable_angles_deg`: `[-30, +30]`.

Angle `theta` is a right-hand rotation about `axis` through `pivot`, measured from the level pose. With `axis = +x`, a positive `theta` raises the +y (far) side.

### 4.2 Rotation and delta

```
R(theta)  = T(pivot) @ Rot(axis, theta) @ T(-pivot)      (rotation_about_axis)
delta(t)  = R(t - cad_pose_angle_deg)                      (delta_transform)
M_world   = delta(t) @ M_cad                               (for group instances)
```

Because the exported geometry is already at CAD pose, `delta(cad) = I`. Only group instances (`Instance.group == g`) and the `field_constants` tag/cell poses for that group get the delta. Static instances never do.

### 4.3 State names

- `"audience"`: the audience-side (-y) cell is raised.
- `"far"`: the far-side (+y) cell is raised.

The mapping is geometric, not hard-coded. `tip_angle(group, state)` applies each stable angle `s` to the offset vector `(0, 1, 0)` about the pivot, using `rotation_about_axis`. The stable angle whose result has positive z is `"far"`; the other is `"audience"`. For `axis = +x` this gives `far = +30`. For an axis of `-x` the same test gives `far = -30`, so no sign flip is needed in calling code.

`state_of_angle(group, angle)` returns the state of the nearest stable angle.

CAD poses: red starts at `audience`, blue starts at `far`. `Field.hive_state` is initialised to match.

### 4.4 Cells and aim points

- `field_constants.hives[alliance].cells[side]` stores `opening_center`, `opening_normal`, and `opening_size_in` at CAD pose.
- The cell that is "up" for a given tip is the one whose transformed `opening_normal` has the largest z. `Field.aim_point(alliance, tip_state)` returns the transformed `opening_center` of that cell. This avoids depending on side naming.

## 5. Module APIs

Contract API (exists in the contract, to be implemented in `sim/`):

- `sim/frames.py`: `ftc_to_pedro(x_f, y_f, h_f)`, `pedro_to_ftc(...)`, `FTC_TO_PEDRO_4x4`.
- `sim/loader.py`: `Instance`, `Mesh`, `FieldModel` (with `get_mesh(key)`), `load_model(model_dir=None, use_cache=True)`, `default_model_dir()`, `CATEGORIES` (16 names), `CATEGORY_PALETTE`.
- `sim/hive.py`: `rotation_about_axis(pivot, axis, angle_deg)`, `tip_angle(group_def, state)`, `state_of_angle(group_def, angle)`, `delta_transform(group_def, state_or_angle)`.
- `sim/field.py`: `Field(model=None)` with `.model`, `.hive_state`, `set_tip`, `toggle_tip`, `instance_transform(inst)`, `tag_ids()`, `tag_pose(id, tip_state=None)`, `aim_point(alliance, tip_state=None)`, `zone(name)`, `zone_names()`, `ball_starts()`.
- `sim/scene.py`: `build_scene(plotter, field, opts) -> SceneHandles` with `set_category_visible`, `set_hive_angle`, `screenshot`.
- `sim/overlays.py`: overlay builders listed in section 1.

Extension points below marked **(proposed)** need a small addition to the contract before they are used.

## 6. Planned extension points

### 6.1 Robot model and drivetrain state

- Add `sim/robot.py` with `@dataclass Robot(pose: np.ndarray (3,), size_in: (w, l), wheel_state: dict, ...)`.
- `pose` is stored in the Pedro frame `(x_p, y_p, h_p)`. Inputs from FTC-frame sources go through `frames.ftc_to_pedro` once, at the boundary.
- Hook: `overlays.robot_box(plotter, robot)` draws the box. `run_sim.py --robot-box --pose x,y,heading_deg` already sets the initial pose in Pedro.
- Hook (proposed): `Field.robot` attribute, so physics and camera code find the robot from the field object. Keep `Field` free of robot logic otherwise.

### 6.2 Pedro Pathing playback and overlay

- Add `sim/paths.py` with `Path(poses: list[(x, y, h)], curves: list[np.ndarray])`, where each curve is a cubic Bezier control-point array in Pedro inches.
- Sampling: evaluate each Bezier at uniform parameter steps, and interpolate heading linearly between poses.
- Playback: a clock advances `t`; the sampled pose is written to `Robot.pose`.
- Overlay: `overlays.path_overlay(plotter, path)` draws the sampled polyline and the pose arrows, using the same Pedro frame as the field.

### 6.3 Shooter ballistic model

- Add `sim/shooter.py`.
- Target: `Field.aim_point(alliance, tip_state)` (contract). Use `Field.tag_pose(id)` to get the goal orientation if a heading or approach constraint is needed.
- Solve launch velocity from the shooter origin (robot pose plus mount offset) to the aim point. With gravity `g` and no drag, the closed form is direct. Drag can be added with a short fixed-step integrator.
- Output: launch velocity vector in Pedro inches per second, consumed by ball physics.

### 6.4 Ball physics

- Initial state: `Field.ball_starts()` (contract), each entry with `center`, `category`, `alliance`, and `diameter_in`. Ball diameter is 5.0 in.
- Collision against the field: transform part meshes into world space with `Field.instance_transform(inst)` and `FieldModel.get_mesh(key)`. For speed, collide against sphere-triangle tests on a coarse subset, or against primitive approximations (boxes, cylinders) per part.
- Hive capture (proposed): add `Field.cell_openings(alliance, tip_state)` returning, for each cell, the opening centre, normal, and size. A ball is captured when its centre crosses the opening disc with `normal . velocity < 0` and it lies within half the opening size. Capture adds the ball to that hive's scored mass.

### 6.5 Hive tipping by scored mass

- Quasi-static model: for each hive, the torque about the pivot is `tau(theta) = sum_i m_i g ((r_i - pivot) x axis) . z_hat`, where `r_i` is each scored ball's centre, transformed by the current `delta_transform`.
- Dynamics: integrate a damped rotation `theta'' = (tau - c theta') / I` with a fixed step. Clamp to the stable range `[-30, +30]`.
- Snap: when `|theta - s| < eps` for the nearest stable angle `s`, set the angle exactly to `s` and update the state with `state_of_angle`.
- Hook: `Field.set_tip(alliance, state)` (contract) when a snap occurs. A continuous angle would need a proposed `Field.set_hive_angle(alliance, deg)`. The scene already supports `set_hive_angle`.

### 6.6 AprilTag camera simulation and localisation

- Camera pose: robot pose (Pedro) plus a fixed mount transform, giving `T_cam_world`.
- Projection: pinhole model with intrinsics `K` (fx, fy, cx, cy) and optional distortion (later). For a tag, project its 4 corners `(+-s/2, +-s/2, 0)` in tag-local space, transformed by `Field.tag_pose(id, tip_state)` and then by `inv(T_cam_world)`.
- Visibility: the tag is visible if the camera lies on the front side of the tag plane, that is `dot(normal, cam_centre - tag_centre) > 0`, and the projected corners fall inside the image with positive depth. Optionally, occlusion can be checked against field primitives using the ray test from 6.4.
- Pose solve: from the 2D corner observations and known tag size, solve PnP. Numpy-only option: direct linear transform for the homography, then decompose with `K`. Note: `cv2.solvePnP` would add an OpenCV dependency, which is not in the current `requirements.txt` plan.
- Localisation: fuse tag-derived robot poses (converted back to Pedro through the camera mount and `tag_pose`) with drivetrain odometry. This is an extended Kalman filter or a simple complementary filter, as later work.

### 6.7 Recording and replay

- Per tick, record a state snapshot: time, robot pose, drivetrain state, `Field.hive_state`, ball centres, and tag observations.
- Storage: JSON lines for readable logs, or `npz` with one array per field for large runs. Both are written to a path chosen by the caller, not to `data/`.
- Replay: read the log, call `Field.set_tip` for hive states, set `Robot.pose`, and let `scene` update actors. Since `Field` state is plain data, a snapshot is the `hive_state` dict plus the robot and ball arrays.

## 7. Testing and invariants

- Frame round-trips: `pedro_to_ftc(ftc_to_pedro(p)) == p` within float tolerance, and the 4x4 matrix agrees with the formulas.
- Hive identity: `delta_transform(group, cad_pose_angle_deg)` is the identity.
- Tip states: `tip_angle(group, "far")` is the stable angle with positive z for the +y offset.
- Aim points: after `set_tip(alliance, state)`, `aim_point` lies on the raised cell.
- Headless import: `sim.field` loads without `pyvista` or `vtk` in `sys.modules`.
- CLI smoke test: `run_sim.py --offscreen --out <tmp>.png` exits 0 and writes a non-empty PNG.
