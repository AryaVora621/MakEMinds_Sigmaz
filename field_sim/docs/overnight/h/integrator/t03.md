## When the panel auto-shows
- Any transition from non-running to running: first Run, Restart (`ar-restart`), or a run started from the planner.
- Also Resume: `ar-pause` on a paused run sets state to running, and AR.prev is 'paused', so the `!== 'running'` check passes and the panel re-opens. This means closing the panel and pressing Resume brings it back. Likely unintended. Proposed fix (not applied): `if (st==='running' && AR.prev!=='running' && AR.prev!=='paused')`.
- Shown only when `S.view==='3d' && !!autoPlanner.runner`. Switching to the planner or Pedro tab hides it without changing AR.show, so it comes back on return to 3D.
- Nothing reopens it after close except a new run start or Resume (above). Stop/done/error do not change AR.show.

Position is an assumption. It is not checked against other fixed elements (#msg, #labels, timeline).

3. app.js, replace the close line 738 tail and add a shared setter:
```js
function setRunPanel(on) {
  AR.show = !!on && !!autoPlanner.runner;               // no run yet: nothing to show
  if (AR.show && S.view !== '3d') setView('3d');
  $('ar-toggle').setAttribute('aria-pressed', String(AR.show));
}
$('ar-close').onclick = () => setRunPanel(false);
$('ar-toggle').onclick = () => setRunPanel(!AR.show);
```
Keep `$('ar-close')` and `$('ar-edit')` wiring as they are. `ar-close` must still hide the panel. `updateAutoPanel` does that each frame.

4. app.js, first line of `updateAutoPanel()` (after line 717):
```js
$('ar-toggle').hidden = S.view !== '3d' || !r;          // only offer reopen when a run exists in 3D
```

5. app.js keydown 3D block (after line 595):
```js
if (k === 'h') setRunPanel(!AR.show);
```
