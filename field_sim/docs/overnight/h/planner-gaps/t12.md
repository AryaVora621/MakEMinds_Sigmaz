## Clipping finding (real)
- The left pane bottom edge is at y=628, but the timeline bar starts at y=604 (#timeline rect 604..684). So the bottom 24px of the left scroll pane sits under the timeline and the last visible row (Commands chips near y 592-604) is cut mid-row.
- Cause (verified from CSS and JS): #autopanel-left/right use `bottom: var(--tl-h, 180px)`. In compact timeline mode autoui.js sets --tl-h to the 56px transport row (autoui.js:731-736). But #timeline has `min-height:80px` (ui.css:194), so the real bar is 80px tall. The 24px mismatch is the overlap.
- Suggested fix (not applied; owner of ui.css/autoui.js decides): make the compact --tl-h match the real timeline height (80px), or drop the min-height to 56px for tl-min. Verify with the same screenshot after the change.

## Other notes
- Clip check: my script flagged 11 'Add ...' chips in the Commands list as 'outside the pane'. They are below the fold inside the scroll container, so this is expected scroll overflow, not a layout clip.
- Path rows' hover actions overlay the meta text ('0 in, 0.0 s') by design (meta goes visibility:hidden). Hover-only actions are not reachable by keyboard unless the row has focus (focus-within is handled).
- Touch or no-hover devices cannot see delete/rename/duplicate until the row is selected. Not tested here.
