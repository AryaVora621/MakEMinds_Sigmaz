## planner.css
- No trajectory-specific custom property. Canvas code cannot read CSS vars anyway.
- Relevant tokens (lines 13-14): `--pl-ok: #4caf50`, `--pl-warn: #ff9800`. These equal `T.ok` and `T.select`/`T.warn`. The colours are duplicated in JS and CSS, not shared.
- `.ap-item[data-on="1"]`, `.ap-node`, and similar rules are UI chrome, not canvas strokes.
- Recommendation: keep canvas colours in JS (one constant object). Do not add CSS vars for canvas strokes.

## Mismatch found
1. Selected path on the autos screen is orange (A). The editor never uses orange for the path itself (B). Two views, two rules.
2. Speed shading exists only in the editor (B). The autos screen (A) is flat colour.
3. Editor colour (B) follows the segment's custom colour. Autos (A) ignores it.

## Proposed shared helper (plannerfield.js)
Add to plannerfield.js (no change to existing exports):

```js
export const TRAJ_COLORS = { plain: '#4caf50', slow: '#ffd600' };   // plain = T.ok (pathui.js:38); slow = yellow end of the speed ramp
/** Yellow (f=0) to green (f=1) speed ramp, the same ramp pathui.js speedColor uses today. */
export function speedColor(f) { const t = Math.max(0, Math.min(1, f)), a = [255, 214, 0], b = [76, 175, 80]; return `rgb(${a.map((v, i) => Math.round(v + (b[i] - v) * t)).join(',')})`; }
/**
 * Dotted trajectory: a dot every `gap` px along the polyline, in screen space.
 * pts: [{x, y, s}] field inches; s = cumulative arc length in inches, last point holds the total.
 * opts: { mx, my } (required, field to screen mappers); r = 2.8; gap = 8; color = TRAJ_COLORS.plain;
 *       speed = null | (f: 0..1 path fraction) => 0..1 (when set, each dot uses speedColor(speed(f)) instead of color); alpha = 1
 */
export function drawTrajectory(ctx, pts, opts = {}) { ... }   // body = pathui.js:484-497 with mx/my/speedColor taken from opts/module scope
```

Body: move `dotted()` (pathui.js:484-497) unchanged, replacing `mx`/`my` with `opts.mx`/`opts.my`, `TAU` already defined in plannerfield.js (line 12), `speedColor` with the exported one. Keep `alpha` as `ctx.globalAlpha` multiply, or let callers keep their own globalAlpha (drawAuto already does at line 530).

3. pathui.js:579 (editor): `drawTrajectory(ctx, line, { mx, my, color: segColor(s) === T.line ? TRAJ_COLORS.plain : segColor(s), r: i === ed.sel ? 3.2 : 2.8, gap: 8, speed: spd })`.
4. pathui.js:588 (zone stretch): leave as is or move to a separate constant; it is not a trajectory.

## Decisions made (no user available)
- D1: The selected path is not orange. Selection = larger dots plus the existing alpha dimming of unselected paths. Reason: one trajectory colour rule across both views. If the user wants orange selection back, set `color: TRAJ_COLORS.selected` (not added yet).
- D2: The autos view gets speed shading only when that path has a planned trajectory. `speedFn` currently reads `ed.traj` (editor route only), so the autos view stays flat green until the autorunner trajectories are wired in (follow-up, owner pathui.js / autorunner.js).
- D3: Custom segment colour stays honoured in the editor only (current behaviour in B). Autos view keeps the plain colour to match the rule "one colour per path".
