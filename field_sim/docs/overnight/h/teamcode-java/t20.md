# t20: Sim-to-Java ball drop/feed path consistency audit

Scope: read-only audit. Nothing edited except this file. No git, no gradle, no tests run.
Method: read the files cited below and grepped web/js and TeamCode/src. Nothing executed.

## Answer summary
- Tip threshold and nectar weight agree across the JS files (8 pollen, 1.75 nectar). Java has only the 8-pollen constant. There is no Java nectar weight or hive-capacity constant that disagrees.
- The sim does NOT drop balls out of a tip. Captured balls become kinematic, stay attached to the hive pivot, and rotate with it. The user's request is not met by the current code.

## Constants
- web/js/hivetip_model.js:72-73: nectarWeight 1.75 (INFERRED), threshold 8. Matches hivecycle.js:53-57 and hivemesh.js:259 (default 1.75).
- TeamCode/src/main/java/commands/field/FieldConstants.java:112-113: HIVE_TIP_POLLEN = 8 [USER-CONFIRMED]. Agrees with JS.
- FieldConstants.java:114: NECTAR_TIP_COUNT is "UNKNOWN" and points to docs/overnight/java-balls.md (that file exists). Java has no nectar weight, so it cannot compute the mixed-ball tip that the JS uses. This is a gap, not a contradiction.
- BallTracker.java:12: MAX_BALLS = 4 (hold limit). Agrees with the rules doc.
- No Java file implements a hive tip counter or tip logic. Robot.java:68 is only a boolean state flag.
- startingNectar = 3 (hivecycle.js:58, hivetip_model.js:49-53) conflicts with a 5-nectar note in docs/overnight/research_manual.md (the conflict is recorded in the JS, and the research file was not reread here). Java has no startingNectar constant.

## Ball release on tip (sim)
- hivecycle.js:59: releaseOnTip: false (default). app.js:286 passes {...HIVE_PARAMS}, so release is off.
- hivecycle.js:21: header says "Balls are not removed by a tip." This states the opposite of the user's request.
- hivecycle.js:216-219: when releaseOnTip is true, the code filters only HiveDynamics.scored. It does not touch BallWorld.balls.
- app.js:441-446: the onTip callback only updates state, aim marks, and the toast. It calls no world release.
- balls.js:465: every step, each ball with state 'scored' is re-placed by _placeScored (balls.js:390-393) from the hive's delta. So captured balls ride the hive rigidly. They do not drop.
- balls.js:338: BallWorld.release(b, vel) exists and is used by flowerarm.js:121. The hive tip path never calls it.
- Result: the tip moves the hive, and the balls stay in the physics world attached to it.

## Ball capture (sim)
- app.js:433-434: onCapture calls hiveDyn.addScoredBall with the ball position, which records a count. The physics ball is kept separately (balls.js:417 sets state 'scored').
- balls.js:405-421: _capture pins the ball into a slot and keeps it in world.balls. Physics bodies are not deleted, but they are kinematic while scored.
- Capture is not a delete: balls stay in world.balls as state 'scored' (balls.js:417).

## Bugs for the 3D sim owner
1. (High) Tip does not release balls. releaseOnTip is false (hivecycle.js:59) and no release happens in app.js:441-446. Fix: enable release on tip, then call world.release(b, vel) for each ball in the lowered cell, and drop them from the hive list.
2. (High) Even with releaseOnTip true, hivecycle.js:216-219 removes records only from HiveDynamics.scored. The BallWorld balls stay 'scored' and are re-placed each step (balls.js:465), so the sim desyncs from the hive counter. Fix: release or remove the physics balls in the same pass.
3. (Medium) hivecycle.js:21 and app.js:286 comments cite "official rule: balls stay in the cell (manual 10.5)". The manual section was not read in this audit, so that claim is UNVERIFIED. The comment conflicts with the requested behaviour and should be reconciled before the change.
4. (Low) balls.js:410-413 recycles a ball from a full cell by removing it from world.balls. HiveDynamics still counts it (noted in the code comment at balls.js:410). The counter and the visible balls can diverge.
5. (Low) hivecycle.js:98: starting nectar is stored in the up cell but not counted. Fine by the stated decision, but the startingNectar 3 vs 5 conflict is open.
6. (Info) Java cannot compute a mixed nectar + pollen tip because it has no nectar weight. If Java ever implements tip logic, use weight, not count (the JS uses weight mode, hivecycle.js:148-156), and take nectar weight from one shared source.

## Java-side gaps

- FieldConstantsBallsTest.java:15-17 checks only HIVE_TIP_POLLEN == 8. There is no nectar or weight test. Add one when a constant exists.
