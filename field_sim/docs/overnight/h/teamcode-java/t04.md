## Pedro's callback API (core/com/pedropathing/paths/callbacks/, package paths/util)
- PathCallback interface: boolean run(); boolean isReady(); default initialize(), reset(), isCompleted(); int getPathIndex().
- Implementations: TemporalCallback(index, startCondition ms, Runnable), ParametricCallback(index, startCondition, follower, Runnable), PoseCallback(follower, pathIndex, targetPoint, Runnable, initialTValueGuess, curve).
- util/FiniteRunAction wraps a PathCallback to run it a set number of times until reset().
- PathChain.setCallbacks(...) sorts by path index, then start condition. PathChain.resetCallbacks() is called from Follower.followPath(PathChain, ...).
- Firing: Follower.update() (core Follower.java ~line 486-530) calls updateCallbacks() ONLY when isBusy && followingPathChain. updateCallbacks() (line ~599) runs each callback whose isReady() is true.
- Follower.java ~line 319-323 and ~553-557 call getNextPathCallbacks(chainIndex) and initialize() on each callback.

## Composing a PathChain follow with a non-blocking AutoAim
Current project code: AutoAim.run(robot, opModeIsActive, timeout, shootAfter, perLoop) is BLOCKING and calls robot.update() in its own loop (commands/autonomous/AutoAim.java lines 1-60, doc comment). Running it from inside a PathCallback would re-enter the update loop. Do not do that.

Recommended composition (no command library needed):
1. Keep one main loop: robot.update() every iteration (drives follower.update() and ShooterBase.update()).
2. Start the path with AutoDrivebase.followPath(chain, holdEnd, timeoutS) (commands/autonomous/AutoDrivebase.java:92).
3. Start aiming when the path reaches the trigger point. Options:
   a. Polling (no callback dependency, safest): check follower.getChainIndex() or getCurrentPathNumber() and/or follower.getCurrentTValue() each loop; when the trigger is met, call a non-blocking aim start that only sets a flag (for example a state machine in AutoAimLogic, which is not yet verified as non-blocking).
   b. PathCallback/TemporalCallback: set only a flag inside run(). Do not call robot.update() or block inside the callback. Depends on the 2.1.1+ fix and on hardware testing (unverified).
4. Each loop: if the aim state machine is active, step it (aim, then feed when ShooterBase.ready()). Finish on ready or timeout.
5. Path completion is tracked by follower.isBusy() / AutoDrivebase.isBusyOrTimeout(), independent of the aim state.
This gives a "follow path while aiming" composition with no new dependency. Whether AutoAimLogic already exposes a non-blocking step is unverified; I did not read it.
