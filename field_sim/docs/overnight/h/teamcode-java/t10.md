## Summary

- Same toggle intent and same per-frame update. Different state machine: Java has dwell, fault and auto-stow; JS has none.
- Ball delivery is not the same: JS fabricates a per-ball feed (pollen only, capped, ballistic). Java has no ball model, so the two cannot match until the CAD and the paddle geometry are known.
- Unverified: all Java timings and angles are placeholders; the "repo" provenance on deployS in flower_arm.json has no matching Java source.
