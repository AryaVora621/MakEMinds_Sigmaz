# a01: parseGLB container and JSON audit (web/js/robotglb.js)

Ran: nothing. Read-only audit of web/js/robotglb.js (308 lines). No tests, no builds, no edits.
Spec: glTF 2.0 (https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html) was NOT fetched. Spec points below are from memory and are unverified against that URL.

## Bugs and unsupported cases (ordered by impact)

1. HIGH, L62 sparse accessors. `readAccessor` throws. The throw propagates to loadRobotGLB (L297-299), so one sparse accessor drops the whole CAD to the procedural robot.
   Fix (text): apply `a.sparse` after the dense read. Read `sparse.indices` (unsigned, own bufferView and componentType) and `sparse.values` (accessor type), then overwrite `out[idx*n+j]`. Do this before normalization.

2. HIGH, L101-102 extension gating. Only `extensionsRequired` containing draco/meshopt is rejected. Any other required extension is accepted silently (spec: loaders must fail on unsupported required extensions, unverified). Draco listed only in `extensionsUsed` surfaces as the generic "primitive without POSITION" error (L119). Meshopt on a bufferView is ignored by readAccessor (L66-72), so the reader can use compressed or placeholder bytes with no error.
   Fix (text): keep a whitelist of supported required extensions and throw on anything else. Throw if any bufferView, buffer or primitive carries EXT_meshopt_compression or KHR_draco_mesh_compression, whether used or required.

3. MEDIUM, L104-113 materials. KHR_materials_* is never read, and nothing warns.
   - pbrSpecularGlossiness: no pbrMetallicRoughness, so L107 falls back to metallic 1, roughness 1, white. The result looks wrong.
   - KHR_materials_emissive_strength: ignored at L105, so emissive is wrong.
   - KHR_materials_unlit, transmission, volume, clearcoat, etc.: ignored.
   Fix (text): warn per material for each unhandled extension. Multiply emissive by emissive_strength. Map pbrSpecularGlossiness diffuseFactor to base colour and mark it as an approximation.

4. MEDIUM, L110 alphaMode. `(c[3] ?? 1) < 1` makes an OPAQUE material transparent. Spec: OPAQUE ignores alpha. MASK is not handled (no alphaTest from alphaCutoff).
   Fix (text): branch on alphaMode. BLEND sets transparent and opacity. MASK sets alphaTest = alphaCutoff (default 0.5). OPAQUE leaves alpha ignored.

5. LOW-MED, L66-72 and L125-133 bufferView bounds. Only the buffer length is checked (L72). The accessor is not checked against `bv.byteLength`, so it can read into neighbouring data (spec requires the accessor to fit its bufferView, unverified).
   Fix (text): also require `(count-1)*stride + size*n <= bv.byteLength` when bv.byteLength is set.

6. LOW-MED, L140-165 node cycles. `objs[i]` is set before recursion (L162-163), so A->B->A returns the ancestor and `o.add()` builds a cyclic scene graph. The depth guard (L142) does not catch this. The failure is a stack overflow later in three's updateMatrixWorld, not a clean Error. Separately, a node with two parents is silently re-parented by o.add (L163).
   Fix (text): keep a visiting set and throw 'glTF: node cycle' when it is hit. Throw on a second parent.

7. LOW, L36-39 container. The spec requires JSON as chunk 0 and BIN second. Any order is accepted. Padding is not validated (L39 rounds silently). Trailing bytes after `total` are accepted (L31 only checks total > length).
   Fix (text): require the first chunk to be JSON. Optionally check padding and warn on trailing bytes.

8. LOW, L49 buffers without uri. Every buffer without a uri gets the BIN chunk, not only buffer 0. Spec: only buffer 0 may omit uri (unverified).
   Fix (text): `if (i !== 0) throw` for uri-less buffers, or check `bin` only for index 0.

9. LOW, L65, L81, L127 index precision. All accessor data, including uint32 indices, is stored in Float32Array. Indices above 2^24 (16,777,216) lose exactness. Not a practical issue for FTC-scale CAD.
   Fix (text): read indices into a Uint32Array directly, bypassing the float path.

10. LOW, missing shape checks. L124 checks NORMAL count but not that it is VEC3. L130-133 do not check that indices are SCALAR. A VEC3 index accessor is read with the wrong stride and wrong values.
    Fix (text): `if (N.n !== 3) skip normals` and `if (I.n !== 1) throw` for indices.

11. LOW, L136 flat CAD. `computeVertexNormals` on indexed geometry averages across shared vertices, so hard edges smooth out when NORMAL is missing.
    Fix (text): call `g.toNonIndexed()` before computeVertexNormals for a faceted look, or weld-aware normals.

12. LOW, L117 primitive modes 5 (strip) and 6 (fan) are dropped with a warning. That loses geometry.
    Fix (text): convert strips and fans to triangle index lists.

13. LOW, L97 version check. `/^2/` also accepts "20" or "2abc". Spec: asset.version is "2.0" (unverified).
    Fix (text): use `/^2\./`.

14. LOW, silent drops with no warning: COLOR_0 (vertex colours), morph targets (`pr.targets`), skins, EXT_mesh_gpu_instancing, KHR_materials_variants, node.camera. Only animations and textures warn (L99-100).
    Fix (text): add a warning for each.

15. INFO, L74-78 performance. Every element goes through `dv[get]` with per-element branching. Large CAD will be slow.
    Fix (text): fast path with `new Float32Array(buf.buffer, off, count*n)` when the stride is tight and the offset is 4-byte aligned, on little-endian hosts.

16. INFO, L16, L91, L94 cross-realm. `instanceof ArrayBuffer` fails for buffers from another realm (iframe, worker). Use `Object.prototype.toString` or `ArrayBuffer.isView` plus a byteLength check.

## Checked and correct (read only)

- Magic, version, and total-length checks: L26-31.
- Chunk bounds check and 4-byte advance: L35, L39. Loop always advances, so no infinite loop.
- Component getters and sizes: L13, L74.
- Normalization formulas: L78 (signed and unsigned divisors, -1 clamp for signed) match the spec formulas (unverified).
- Index widths uint8, uint16 and uint32 are read correctly: L74.
- Metallic and roughness defaults of 1: L107.
- Matrix is column-major: L149 uses Matrix4.fromArray, which is column-major.
- Missing normals are computed: L136.
- Node TRS handling and quaternion normalize: L151-153.
- Scene and root fallback: L166-173.

## Intentional deviation (not a bug)

- L114 defMat is grey (0xaaaaaa, metal 0.3, rough 0.6). Spec default material is white, metal 1, rough 1. Looks deliberate; note only.
