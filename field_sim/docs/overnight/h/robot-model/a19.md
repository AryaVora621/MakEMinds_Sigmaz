# a19: robotmodel.js procedural geometry cleanup / dispose audit

Ran: read web/js/robotmodel.js (557 lines) in full; grep of web/js/app.js and robotglb.js for the swap path; read web/data/robot_spec.json; grep of web/vendor/three.module.js for REVISION.

## Three.js version
- web/vendor/three.module.js:6 `REVISION = '170'` (r170). Import map at web/index.html:257 maps `three` to this file.
- Removed APIs in r170 (Geometry, Face3, outputEncoding/sRGBEncoding, THREE.Math): none used in robotmodel.js or flowerarm3d.js. Used APIs (Shape.absarc, Path, ExtrudeGeometry, TubeGeometry, CatmullRomCurve3, Matrix3.getNormalMatrix, Vector3.applyMatrix3, Float32BufferAttribute, BufferGeometry.toNonIndexed) all exist in r170.

## Disposal (procedural -> CAD swap)
- No dispose API. buildRobot returns `{group, turretGroup, hoodPivot, flywheelMesh, parts, setPose, animate, state}` (robotmodel.js:553). No `dispose()` and no `removeFromParent`.
- Only dispose calls are inside makeBatch.add: robotmodel.js:56 `g.dispose(); geo.dispose();` on temporary input geometry, which is correct.
- Leaks: `M` materials created per call (robotmodel.js:87-98) are never disposed. Direct `mesh()` geometries are never disposed: roller geometry shared across 9 rollers (255, 261), per-roller pin CylinderGeometry (263, 36 instances), gate/bumper/camera/sensor boxes (230, 330, 372, 441, 469, 481-498).
- Swap path, app.js:248-258: built.group is added to the scene, then on a CAD load every robot child gets `visible = false` (app.js:253). Nothing is removed or disposed, so procedural GPU buffers stay resident for the whole session. Fix: add `dispose()` that traverses the group, calls geometry.dispose() and material.dispose() (dedupe with a Set), then `group.removeFromParent()`.
- Rebuild (calling buildRobot twice) leaks the first set for the same reason.
- Also flowerarm3d.js:32-38 creates its own geometries and materials; it is kept visible in the CAD case (app.js:255), so it must not be disposed by the swap.

## Shadows
- mesh() (robotmodel.js:100-103) sets castShadow and receiveShadow true. All kit().flush() output and most direct meshes go through it.
- Exceptions: rollerPin castShadow=false (robotmodel.js:263) and receiveShadow left false on it. The glass ball column (441) casts a shadow; it is translucent (opacity 0.22) and probably should not (candidate fix, not verified visually).
- flowerarm3d.js:38 sets castShadow only, no receiveShadow (cylinder). Minor.
- robotglb.js:266 sets both flags on CAD meshes, so the CAD path is consistent.

## Material sidedness and colour space
- DoubleSide: glass (robotmodel.js:96, transparent, depthWrite false) and hoodShell (98). Both are open or thin surfaces, so this is appropriate. Sector cheek plates (471) are closed extrusions with default FrontSide.
- Colour: all colours are hex literals passed to THREE.Color (default ColorManagement in r170, output SRGB by default). No colorSpace or outputEncoding is set anywhere in web/js (grep). Treated as sRGB, which is consistent. Not verified visually.

## Recommendations
1. Add dispose() to buildRobot's return and call it from app.js when the CAD loads (app.js:253). Dispose flowerarm3d.js meshes only if they are not reused.
2. Make the roller and pin geometries shared (one per size) to cut the 36 pin and 4 roller geometries.
3. Set castShadow=false on the glass column (441).
4. Add ASSUMED/TODO tags for the constants above, starting with the 422 ring radius mismatch and the 346 transfer roller radius.
