## Return-object shape mismatch
- buildRobot returns {group, turretGroup, hoodPivot, flywheelMesh, parts, setPose, animate, state} (robotmodel.js:553).
- loadRobotGLB/placeCAD returns {group, scale, units, warnings, bounds, parts} (robotglb.js:268-273).
- M1: turretGroup, hoodPivot, flywheelMesh, setPose, animate, state exist only on the procedural result.
- M2: `parts` means different things. Procedural parts keys (robotmodel.js:157-160): chassis, wheels, intakes, intakeRollers, transferRollers, flower, flowerArm, gate, pods and more. CAD parts is the findMovingParts result {turret, hood, flywheel, found, missing} (robotglb.js:217, 231). A caller doing model.parts.wheels gets undefined, and so on.
- M3: app.js:260 reads built.turretGroup, hoodPivot, flywheelMesh unconditionally. On the CAD path these are the procedural nodes that app.js:253 has just hidden, so turret, hood and flywheel motion is silently invisible on the CAD model.
- M4: app.js:1072 calls built.animate. Swapping `built` for the CAD result would throw a TypeError, because no animate exists there.
- M5: app.js:251 uses tryLoadRobotGLB, which returns {model, reason} (robotglb.js:304-306). The plain loadRobotGLB returns model or null (robotglb.js:281-300). MODEL_README.md:18 describes only the null behaviour, so it is slightly misleading.
- M6: placeCAD never warns when findMovingParts reports missing keys (robotglb.js:271). The app does not surface the missing list, so a CAD export with unnamed parts loads with no animation and no message. MODEL_README.md:43-45 implies the names are used.
- M7 (minor): app.js:1067-1068 and animate (robotmodel.js:510-511, via app.js:1072) both set turret and hood. Same value, so harmless, but duplicated.

## Caveats
- A CAD export has no wheel, intake, transfer, flywheel or turret node names mapped except the three in DEFAULT_NAMES (robotglb.js:201-205).
- findMovingParts matches substrings, so a generic name containing "hood" or "turret" could be picked up.
- The CAD path needs parts.turret, hood and flywheel bound to the same transform conventions as the procedural ones: turret about z, hood about y with a negated sign, flywheel about y. None of this is checked in code.
- Not verified at runtime: whether the browser renders the CAD path at all.
