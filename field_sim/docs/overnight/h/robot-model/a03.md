# a03: Audit of auto-fit to the 381 x 375 mm frame (placeCAD)

Scope: read only. Edited nothing except this file.

## Where the 381 x 375 mm target lives
- No literal `381` or `375` in web/js/robotglb.js, web/js/robotspec.js or web/data/robot_spec.json.
- The target is stored in inches as `chassis.footprint` = [[-7.5,-7.38],[7.5,-7.38],[7.5,7.38],[-7.5,7.38]] (robot_spec.json:14, units "in" at line 4).
- 15.00 in = 381 mm exactly. 14.76 in = 375 mm (14.764 in, 0.004 in rounding).
- Tests that pin it: tests_js/robotspec.test.mjs:34-36 and tests_js/robotmodel.test.mjs:70 (`381` check).
- Target used by the fit: footprintTarget() (robotglb.js:193-199) = max of footprint x and y extents = 15 in.

## Checklist
1. Chassis-only bounding box: FAIL. robotglb.js:244 `Box3().setFromObject(outer)` takes every mesh. rawW (247), the scale guess (249-258), and the centre (261-263) all use the whole model, so intake, turret, hood, flower arm and the 4.2 in deployed intake count. The header at robotglb.js:7 says "chassis bbox centred on x=y=0", which the code does not do.
2. Uniform scale: PASS. Single `scaleG.scale.setScalar(scale)` (robotglb.js:259).
3. Unit heuristic (m / cm / mm / in): PARTLY OK. Nearest log-ratio of rawW against 15 in (robotglb.js:253-255). The candidates are spaced 2.54x or more apart, so a protrusion does not flip the choice. The warning at 256-257 only fires when the chosen unit is still outside 0.6 to 1.4 of target, so it is weak. It checks width only, not height (chassis.height = 18).
4. Explicit `opts.units` skips the sanity check: GAP. robotglb.js:250-251 never compares to the footprint. An unknown unit string (e.g. 'ft') silently falls through to the heuristic.
5. XY centre: FAIL in intent. Centre is the whole-bbox centre (262-263). If the intake or flower arm is off-centre, the chassis is off-centre relative to the spec footprint, which is centred on 0,0 (collision uses it).
6. Z floor: PARTIAL. offsetG.position z = -b2.min.z (263). Floor is the lowest point of any part. Correct only if the wheels are the lowest geometry.
7. Output in inches: PASS. Spec units "in" (robot_spec.json:4), the footprint is in inches, and the fit scales to inches. So the sim unit is inches (Pedro frame, same as the rest of the sim). 381 mm -> 15.00 in; 375 mm -> 14.76 in.
8. Orientation default: MISMATCH. The doc example at robotglb.js:9 uses upAxis 'Z'. app.js:251 passes `{}`, so orientationMatrix uses its default upAxis 'Y', forwardAxis '+X' (robotglb.js:182). The Onshape export axes are unverified.
9. Spurious FTC warning: GAP. robotglb.js:267 warns if the full bbox exceeds 18.5 in. A deployed intake (4.2 in) on a 15 in chassis gives about 19.2 in and fires a false alarm.
10. `offset` option: UNDOCUMENTED SIGN. robotglb.js:263 subtracts opts.offset. Nothing in app.js uses it.

## Bugs and gaps (file:line, fix)
- robotglb.js:244-263. Fit to chassis only. Fix: find the chassis node (name match like findMovingParts, e.g. /chassis|drivetrain|base/i), or compute the bbox from the footprint-plane meshes only. Use that bbox for rawW, the scale, and the XY centre. Keep the Z floor on the full bbox or the wheel bottom.
- robotglb.js:257-258 and 250-251. Always check against the footprint, including explicit units. Fix: after scaling, compare the chassis bbox to footprintTarget and push a warning if off by more than 5%. Add a height check against spec.chassis.height.
- robotglb.js:7 vs 244-263. Header and code disagree. Fix: change the header to say "full-model bbox" until item 1 is fixed.
- robotglb.js:267. False FTC warning with deployed mechanisms. Fix: compare the folded envelope, or warn at 19 in with a note that intake deploys.
- app.js:251. No orientation or units passed. Fix: pass `{ orientation: { upAxis: 'Z', forwardAxis: '+X' } }` once the Onshape export axes are checked, or log the chosen units in diag.
- robotglb.js:263. Undocumented offset sign. Fix: document it as "shift the model by +offset in inches" and flip the sign.
