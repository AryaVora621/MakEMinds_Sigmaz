# a08: Onshape export formats and API options

Scope: public docs only. The private Onshape document was NOT accessed (per task rule). Everything below comes from WebFetch/WebSearch of the cited pages, not from the document itself.

## 1. UI export (verified from help page)

Source: https://cad.onshape.com/help/Content/File/exporting_files.htm (fetched)

Steps (desktop):
1. Right-click the Part Studio or Assembly tab.
2. Click "Export".
3. Set options in the Export dialog.
4. Click "Export".
Multiple tabs: Tab manager, Ctrl+click to select, right-click, Export. Part Studios and Assemblies cannot be mixed in one export.

Format list: PARASOLID, ACIS, STEP, IGES, PVZ, JT, RHINO, GLTF, GLB, OBJ, 3MF, URDF (Assembly only), STL.

Options (exact labels):
- "File name" (defaults to tab name)
- "Export models oriented Y axis up" (reorients model; the page does not state the default orientation)
- "Resolution" (GLTF, GLB, OBJ, 3MF, STL, URDF): Coarse / Medium / Fine / Custom
- "Compress" (GLTF and GLB only; non-mesh geometry not compressed)
- "STL Format": Text or Binary (STL only)
- "Units" (STL only): Centimeter, Foot, Inch, Meter, Millimeter, Yard
- "Use custom units for export" (STEP only): Centimeter, Foot, Inch, Meter, Millimeter; unchecked means Meters
- "Preprocessing" (STEP only)
- "Export unique parts as individual files": unchecked = one file; checked = one file per part in a zip
- "Options": Download / Download and store file in a new tab / Email with link (not on Free or Education) / Store file in a new tab

Note: the help page does not list a glTF unit selector. Per-part export is via the "Export unique parts as individual files" checkbox.

## 2. REST API export endpoints (verified from API page)

Source: https://onshape-public.github.io/docs/api-adv/translation/ (fetched)

Async (POST), Part Studio:
- POST /partstudios/d/{did}/{wv}/{wvid}/e/{eid}/export/gltf
- POST /partstudios/d/{did}/{wv}/{wvid}/e/{eid}/export/obj
- POST /partstudios/d/{did}/{wv}/{wvid}/e/{eid}/export/step
- POST /partstudios/d/{did}/{wv}/{wvid}/e/{eid}/translations (any format)

Async (POST), Assembly: same pattern under /assemblies/.../export/{gltf,obj,step} and /translations (Parasolid via parasolidMode "BINARY").

glTF body example from the page: angularTolerance 0.001, distanceTolerance 0.001, maximumChordLength 0.01, resolution "FINE", unit "METER", storeInDocument true.

Sync (GET), confirmed by the page:
- GET /partstudios/d/{did}/w/{wid}/e/{eid}/stl?mode=text&grouping=true&scale=1&units=inch
- GET /parts/d/{did}/w/{wid}/e/{eid}/partid/{pid}/parasolid?version=0
- Other sync exports listed by name only (Part glTF, Part STL, Part Studio glTF, Part Studio Parasolid). No path shown. Sync Assembly exports not listed.
- Sync exports return a 307 redirect to download the file.

Polling: GET /translations/{translationId}. Poll until requestState is DONE or FAILED. Webhooks are an alternative.
Download: GET /blobelements/d/{did}/{wv}/{wvid}/e/{resultElementId}, accept application/octet-stream.

Caveat: the page's examples use mixed API versions (v6, v9, v11). The Quickstart uses v10 (https://onshape-public.github.io/docs/api-intro/quickstart/). Pick the current version from the API Explorer: https://cad.onshape.com/glassworks/explorer/ (not fetched in this run; UNVERIFIED for current version).

GLB: the translation page does not mention GLB. GLB appears only in the UI format list. Whether POST .../export/glb exists is UNVERIFIED.

## 3. Authentication (verified)

Source: https://onshape-public.github.io/docs/api-intro/quickstart/ and https://onshape-public.github.io/docs/auth/apikeys/ (both fetched)

- Basic auth (local testing only per API Keys page): base64("ACCESS_KEY:SECRET_KEY") in header `Authorization: Basic CREDENTIALS`. Python example uses requests auth=(access_key, secret_key).
- Request signing (HMAC-SHA256): headers `Date`, `On-Nonce`, and `Authorization: On <AccessKey>:HmacSHA256:<Signature>`. Signed string = method, nonce, date, content-type, path, query, newline-separated, lowercased. The signature is base64 of HMAC with the secret key. Full signing spec is on the API Keys page.
- Access key identifies the key; secret key is the HMAC key. Keep the secret private.
- Base URL: https://cad.onshape.com/api (Enterprise: https://companyName.onshape.com/api).
- Key creation: My Account > Developer, then "API keys" > "Create new API key" (https://cad.onshape.com/help/Content/Plans/developer-myaccount.htm, cited by the API Keys page). Company/Classroom/Enterprise: "Company/Classroom/Enterprise Settings - Developer" (https://cad.onshape.com/help/Content/Plans/enterprise_settings_developer.htm).
- Key cap: individual accounts max 2 active keys; company/classroom/enterprise uncapped.
- The task said dev-portal.onshape.com. That host was NOT confirmed by any cited page. UNVERIFIED.
- The earlier search summary said HMAC was for webhooks only. The API Keys page says HMAC signing applies to REST requests. The fetched page wins. The webhook HMAC is a separate matter.

## 4. Rate limits and quotas

Source: https://onshape-public.github.io/docs/auth/limits/ (fetched)

- Per-endpoint rate limit values are NOT published on that page ("vary by endpoint"). Exceeding a limit returns HTTP 429. Retry-After and X-Rate-Limit-Remaining headers were mentioned by a search summary only, not on the fetched page. UNVERIFIED.
- Annual quotas per account type (calls from API keys count):
  - Enterprise / Enterprise GOV: 10,000 per Full User in Company
  - Professional: 5,000 per User in Company
  - EDU Student, Free, Standard: 2,500 per User
  - EDU Enterprise: 10,000 per Enterprise
  - EDU Educator, Pro Discovery: 2,500 per Company
- After the annual cap: HTTP 402 for further requests.
- Only 2xx and 3xx responses count toward annual limits for API key and private-app OAuth2 calls. 4xx and 5xx do not.
- Error codes: https://onshape-public.github.io/docs/api-adv/errors/ (linked, not fetched).

## 5. glTF axis and units (mostly UNVERIFIED for Onshape)

- Onshape default axis: the export dialog has "Export models oriented Y axis up", which implies the default is not Y-up. Inference only. UNVERIFIED.
- Onshape glTF unit: not stated on any fetched page. The API body example sets unit "METER" for the async glTF call (https://onshape-public.github.io/docs/api-adv/translation/). So the API path can request meters. The UI unit choice for glTF is not documented.
- glTF 2.0 spec convention: Y-up, meters. This is from general knowledge of the Khronos spec, not from a fetched page here. Spec URL not fetched in this run: https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html (UNVERIFIED in this run).
