# a06: graceful fallback to the procedural robot (audit)

Method: read-only. I read web/js/robotglb.js, web/js/app.js, web/js/robotmodel.js, web/js/diag.js and web/data/MODEL_README.md, and grepped web/ for callers. I did NOT run the code, the tests, or a browser. No files were edited (only this report was written).

## Callers (grep of web/)
- web/js/app.js:21 imports tryLoadRobotGLB; web/js/app.js:251 is the only runtime caller.
- loadRobotGLB is called only from tryLoadRobotGLB (web/js/robotglb.js:305).
- buildRobot is called at web/js/app.js:248 (defined web/js/robotmodel.js:84).
- findMovingParts is NOT called anywhere in web/js or app.js. Only robotglb.js:213 defines it and MODEL_README mentions it.
- No web/js/main.js exists in the grep hits.

## Checks
1. Missing robot.glb (404) falls back: PASS for the fallback itself. robotglb.js:291 returns fail() on !r.ok, and app.js:258 shows the procedural note. FAIL for "with a console warning": fail() (robotglb.js:282) only sets lastReason and emits no console.warn. app.js:251 discards r.reason, so the HTTP 404 text never reaches the console or UI. The browser may log its own network error, which is not ours.
2. Corrupt GLB falls back: PASS. parseGLB throws (robotglb.js:26-41, 97, 102), loadRobotGLB catches at robotglb.js:297-299 and returns null.
3. GLB with zero meshes falls back: PASS. No nodes gives "scene is empty" (robotglb.js:173). Nodes with no geometry give an empty Box3 and "CAD has no geometry" (robotglb.js:245). Both are caught.
4. Partial success (CAD loaded, no named parts) still animates something: FAIL. findMovingParts is never called (app.js has no reference). The CAD group (app.js:254) is static. The procedural turretGroup, hoodPivot and flywheelMesh are hidden at app.js:253 (they are direct children of the robot group, robotmodel.js:415, 448, 450). app.js:1067 and 1072 still rotate those hidden objects, so the CAD turret, hood and flywheel never move. Only the whole body moves with the robot, since the CAD is a child of robot (PASS for that narrow claim). The flower arm is kept visible at app.js:255 by design (robotmodel.js:394 adds it as a direct child, so the visibility flip works).
5. Promise rejection never unhandled: PASS. app.js:251 has .catch. loadRobotGLB has try/catch around all work (robotglb.js:284-299), and tryLoadRobotGLB cannot reject (robotglb.js:305). Note: the top-level await at app.js:251 blocks module startup until the fetch resolves. A hanging fetch would stall the sim (minor).
6. Procedural robot disposed or hidden when CAD replaces it (no double robot): PASS for no double robot, with a caveat. app.js:253 hides every top-level child of robot, then app.js:254 adds the CAD. Nothing is disposed (no .dispose() call), so the hidden geometry and materials stay in memory. Hidden children do not render or cast shadows. Not verified in a browser.
7. Fallback status surfaced in UI/console: PARTIAL. UI: PASS. app.js:257 and 258 set a sim note via diag.setSimNote (diag.js:173-176, rendered into notesBox). Console: FAIL. The fallback path emits no console message. The only toast is for CAD warnings on success (app.js:256). The specific reason is not surfaced anywhere, although MODEL_README.md:18-19 says it is in loadRobotGLB.lastReason.

## Summary
PASS: 404 fallback (silent in code), corrupt GLB, zero meshes, promise safety, no double robot.
FAIL: fallback reason not logged or shown (app.js:251-258), partial success leaves turret, hood and flywheel frozen on the CAD (app.js:253, 1067, 1072), findMovingParts unused (robotglb.js:213).

## Follow-ups for other owners (not edited)
- app.js:251-258: keep r.reason; call console.warn(r.reason) and a toast on fallback.
- app.js:253-254: after placing the CAD, call findMovingParts(r.model.group) (or use r.model.parts) and drive those CAD nodes from built.animate, or hide the procedural turret, hood and flywheel only when the CAD equivalents are found.
- Optional: dispose hidden procedural geometry, or keep the reference for a fast toggle.
