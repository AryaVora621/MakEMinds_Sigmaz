# t11: javac check of exported ivy sample (lead pedro-compat)

Result: the ivy-style export compiles with javac 17.0.12 against hand-written stubs. This verifies syntax and internal generics/signature consistency only. It does NOT verify the real Ivy or Pedro API.

## What ran
- Exporter: node ESM import of `web/js/autoexport.js`, `exportAutoJava(auto, {className:'IvySample', style:'ivy'})`. Sample auto is the one from `tests_js/autoexport.test.mjs` (paths a/b, sequential with follow, parallel[intakeOn, wait], waitUntil gateOpen, follow b). Script: `<scratch>/t11/gen.mjs`. Output: `<scratch>/t11/IvySample.java` (96 lines, exit 0).
- Ivy jar search: `~/.gradle/caches` and `~/.m2`. No Pedro/FTC Ivy jar present. The only "ivy" hits are Gradle's own `gradle-ivy-8.9.jar` and `ivy-2.5.2.jar` under `~/.gradle/wrapper/dists/gradle-8.9-bin/...`. Those are Apache Ivy (a dependency resolver), not the robotics Ivy library. Not used.
- Docs search: one WebSearch ("pedropathing ivy PedroCommands sequential parallel follow waitUntil Scheduler documentation"). No Ivy API documentation found. Results were deepwiki.com, context7.com, pedro-pathing.github.io Auto docs, barrow-robotics Docs. None document PedroCommands, Scheduler, or waitUntil. So no doc URL backs the stub signatures.
- Stubs (labelled "STUB, NOT REAL API" in each file) in `<scratch>/t11/src/`: `com.pedropathing.ivy.Scheduler`, `com.pedropathing.ivy.pedro.PedroCommands` (Command, sequential, parallel, race, deadline, follow, instant, waitSeconds, waitUntil), plus minimal Pedro (Pose, BezierLine, BezierCurve, PathChain, Follower), FTC (LinearOpMode, Autonomous, ElapsedTime, HardwareMap, Telemetry), `robot.Robot`, `commands.field.Alliance`. Stub signatures come from the exporter's own comments and calls (`web/js/autoexport.js` lines 386-483), not from any source.
- Command run: `javac -Xlint:all -d out $(find src -name '*.java')` (stubs plus sample). Exit 0, no warnings.
- Also run: `javac -Xlint:all -d out3 -sourcepath src src/commands/autonomous/IvySample.java`. Exit 0.

## Errors
- Final run: none.
- One earlier failure, `duplicate class: commands.autonomous.IvySample`, was caused by my scratch setup (I copied the sample to a stray `src/IvySample.java`). It was not an exporter error. Fixed by deleting the stray copy.

## What the exporter output depends on (all stub-only, so UNVERIFIED against real Ivy)
- `import static com.pedropathing.ivy.pedro.PedroCommands.*;`
- `com.pedropathing.ivy.Scheduler.schedule(...)` and `.execute()`. The exporter itself marks these UNVERIFIED (lines 466, 483).
- `waitSeconds`, `waitUntil`, and `instant(Runnable)`. The exporter marks waitSeconds/waitUntil UNVERIFIED (lines 393-394).
- `follow(Follower, PathChain)`. The exporter's comment says it "may need a Path, not a PathChain" (line 452). The stub uses PathChain, which may be wrong.
- Generated exporter comment line 15-16 says Ivy is not a project dependency and gives the gradle line `com.pedropathing.ivy:pedro:1.1.1`. I did not verify that coordinate exists.
