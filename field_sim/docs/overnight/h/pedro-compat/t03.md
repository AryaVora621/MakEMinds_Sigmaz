## Behavior read from source (Follower.java)
- `followPath(PathChain, boolean)` delegates to `followPath(chain, globalMaxPower, holdEnd)`.
- `followPath(PathChain, maxPower, holdEnd)`: calls `breakFollowing()`, sets `holdPositionAtEnd = holdEnd`, `isBusy = true`, `followingPathChain = true`, `chainIndex = 0`, stores chain, then calls `resetCallbacks()` and `getNextPathCallbacks(0)` and runs each callback's `initialize()`.
- `isBusy()` returns the field. It is set true at path start and at each chain segment advance (`chainIndex++`), and set false in `breakFollowing()` and `pausePathFollowing()`. Also set false when the turn-in-place hold finishes (`isTurning`).
- Chain advance happens inside `update()` when `isBusy` is false and `chainIndex < size()-1`. Calling `update()` while `isBusy` is true only refreshes `previousClosestPose`.
- Hold-at-end: `holdingPosition` is handled in `update()`; `isBusy` only goes false on turn completion while holding.
- Callbacks: chain callbacks are queued via `PathChain.getNextPathCallbacks(chainIndex)` and invoked by `Follower.updateCallbacks()` (called from `update()` at line 524 when `followingPathChain`). Source does not show why the project reports they never fire; this is unverified at runtime.
