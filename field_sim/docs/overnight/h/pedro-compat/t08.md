# t08: ppformat.js round-trip audit (read-only, no tests run)

Scope: web/js/ppformat.js (127 lines), tests_js/ppformat.test.mjs, tests_js/ppformat_autoaim.test.mjs.

## What ppformat.js produces
Visualizer ProjectDoc 2.0.0 JSON, written as:
- version "2.0.0", timestamp, name, alliance (name and alliance are not in the Visualizer ProjectDoc; ignored by its loader)
- startPoint {x, y, headingDeg}
- lines[] {id "line-N", name, color, locked, kind "atomic", endPoint, controlPoints, heading, biobuzz{callbacks, speed, reversed, type, hidden}}
- shapes [], fieldPoints [], sequence [{kind "path", lineId}], activePaths [line ids]
- heading: {type "linear", startDeg, endDeg} | {type "constant", degrees} | {type "tangential", reverse}

Header open question resolved: the heading discriminator is `type` (types.ts Heading union, lines 39-43; fixtures use "type"). The importer's tolerance for `mode`/`kind` is extra and harmless. The `.pp` extension is the Visualizer's LEGACY_PROJECT_EXTENSION (src/utils/filename.ts:5), so it is still the file name.

## Fields dropped or mis-named vs official format
1. activePaths: ppformat writes line IDs. Official meaning is "other saved files shown alongside this one" (project.ts:36; overlays load these as file paths, state/overlays.svelte.ts:36). Mis-used. Fix: write [].
2. "eventMarkers": no such key exists in the Visualizer source, types, or fixtures. Timed markers in the official format are waits: waitBeforeMs/waitAfterMs plus waitBeforeName/waitAfterName per line (normalize.ts:162-171; fixture features-1.5.pp), or sequence items {kind "wait", id, name, durationMs} (types.ts:105-111). Our event markers are segment `callbacks` [{t, name, args}] stored only in biobuzz. This is a project extension, not the official format.
3. Waits: never emitted; the importer drops sequence wait items with a warning (line 96; test 'importer ignores unknown keys' asserts this). waitBeforeMs/waitAfterMs are never read. Waits do NOT round-trip.
4. Compound groups (kind "compound", segments[], group heading, types.ts:84-88): export never writes them; import flattens to the last child with a warning (line 104). Command subgroups have no representation, so they do NOT round-trip.
5. throughPoints (types.ts:78; normalize.ts:199): not emitted, not read. Dropped.
6. heading piecewise (piecewiseHeading.segments, types.ts:19-37, 42): import degrades to tangential with a warning (line 68). Export never writes it. Lossy.
7. robot block (migrations.ts; robot.ts): not emitted, so the loader uses its fallback. Robot settings (rLength, rWidth, velocities) are not carried.
8. shapes and fieldPoints: emitted as [] always, so obstacles and field points are lost on export. Confirm whether the route model has them before treating this as a bug.
9. Point-level name/locked on endPoint and startPoint.name: not emitted (minor).
10. biobuzz: Visualizer normalizePaths (normalize.ts:175-205) rebuilds each line from named fields, so biobuzz and the top-level name/alliance are lost whenever the Visualizer re-saves. Our extras survive only our own loop.

## Round-trip status (per the code and tests, not executed)
- Preserved: geometry (endPoint, controlPoints), linear/constant/tangential headings, colour, label, locked, speed, callbacks (incl. autoAim shootAfter boolean), reversed, hidden, startPoint x/y/heading. Covered by ppformat.test.mjs 'round trip preserves geometry...' and the 6 autoAim tests.
- Preserved only in our loop: segment callbacks and speed (inside biobuzz).
- NOT preserved: waits and wait sequence items, compound/command groups, throughPoints, piecewise headings, robot, shapes, fieldPoints.
- Markers: our callbacks are not in any official field. They do not survive a Visualizer re-save, and the Visualizer shows no marker for them.

## Test coverage gaps
- No test imports the official fixtures (test/fixtures/projects/*.pp, e.g. features-1.5.pp). Official-file compatibility is untested.
- No test asserts that waits or groups are lost (there is only the implicit wait-warning test).

## Recommendations (for the owner of ppformat.js; I did not edit it)
- Set activePaths to [] on export.
- Export waits as waitBeforeMs/waitAfterMs (+ names) where the route model has them, and as sequence wait items. Import the same way instead of dropping them.
- Decide whether command groups map to kind "compound" (export and import), then remove the flattening warning.
- Add a test that loads each fixture in test/fixtures/projects/*.pp via ppToRoute and checks the warnings list.
- Document biobuzz as a non-official extension in the file header; keep the callbacks there.
