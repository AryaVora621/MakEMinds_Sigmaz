Follower update: the generated loop calls `robot.update()` every tick (L482). `Robot.update()` calls `auto.update()` (Robot.java L193), which calls `follower.update()` (AutoDrivebase.java L143). So a follow branch inside parallel/race keeps being driven while its siblings run. Generated code never calls `follower.update()` itself.

Double-follow risk: YES, confirmed by sample output. Two follow nodes that are live in the same tick (parallel, race, deadline, or a follow in one branch with a follow in another) both emit `robot.auto.followPath(...)` in the same tick (sample `race_two_follows`: state 1 and state 2 both call followPath in run0's branch order). Nothing checks for this.

## Bugs (line numbers in web/js/autoexport.js)

- **B1 (high) concurrent follows share one follower.** L308 (follow state), L351/L356/L369 (composites). Each live follow calls `robot.auto.followPath`. The last call wins: the earlier path is dropped, and `moveTimeoutS` is overwritten (AutoDrivebase L92-94, L226). When the losing branch is cancelled, `cancelMove()` -> `holdPoint()` (AutoDrivebase L188-190) stops the motion of the winner too. Fix: validate in the exporter (reject or warn when >1 follow is live under parallel/race/deadline), or sequence them.
- **B2 (medium) the tree is not checked for B1.** `checkJavaStructure` (L535+) does not catch it. Generated Java compiles and runs; the bug is behavioral.
- **B3 (medium) waitUntil with no timeout hangs forever.** L315 `return false; // no timeout set`. Unlike follow (FOLLOW_TIMEOUT_S), there is no default bound. Suggest a default or a warning.
- **B4 (low) waitUntil timeout is reported as success.** L315 returns true on timeout, with no flag. In a race, a timed-out waitUntil wins the race.
- **B5 (medium) unknown condition names silently return false.** L282 stub `return false;`. The exporter emits no warning; the name is only listed as a TODO stub.
- **B6 (low) stub name collisions.** L107 and L281 use `ident()`, which maps `a-b` and `a_b` to the same method name. Duplicate method = compile error. The stub map key (L108, L282) uses the raw name, so both get emitted.
- **B7 (low, rule) invented durations.** L335 defaults shoot=1.0 s and shootAll=3.0 s. Not marked ASSUMED or TODO. Rule: do not invent robot constants.
- **B8 (medium) single `autoAimCmd` field.** L188-195 (stub) and L194. Two autoAim markers (same or different paths) overwrite the field; the first aimer is abandoned mid-run and its intake state is left as-is.
- **B9 (low) autoAim cancel leaves the flywheel spinning.** L332 cancel only stops intake; `setSpinning(true)` (L330-ish state setup) is not reverted when a race loser is cancelled.
- **B10 (cosmetic) unused flags and cancel helper.** L355 race `flags` never used; L358 `cans2` only used in cancel.
- **B11 (cosmetic) label text.** L315 comment `waitUntil ballCount3` (cmt() strips `>=`). Harmless.
