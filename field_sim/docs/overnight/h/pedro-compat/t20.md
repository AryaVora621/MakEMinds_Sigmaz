## 5. Semantic differences: sim runner vs exported Java (emitStateMachine, autoexport.js ~289-375)
1. Deadline index out of range: validator errors (`bad-deadline`); Java clamps silently to 0 (autoexport.js:362). Sim does NOT clamp: `buildCommandTree` uses `kids[di]` (autos.js ~line 483), which is undefined. Behaviour in sim is likely a thrown error. UNVERIFIED (not executed).
2. Race cancellation: both cancel the losers and stop stepping later branches in the winning tick. Equivalent by reading.
3. Parallel completion: both end when every branch has ended; zero-child groups finish immediately in both. Equivalent.
4. Deadline: both run the decider first and cancel the others when it ends. Equivalent.
5. waitUntil: both check predicate first, then timeout (`>=`). Java uses wall clock (ElapsedTime), sim uses fixed-step dt. Same semantics, different clock.
6. wait: both simple elapsed-time checks. Same.
7. Follow timeout: Java follow gives up after FOLLOW_TIMEOUT_S (autoexport.js ~458, `isBusyOrTimeout`). Sim follow has no timeout; it only ends when the sampled path or trajectory ends. Divergence: Java can move on early when stuck, sim cannot.
8. autoAim timeout source: sim `buildCommandTree` passes `args.timeout` (undefined in practice, since autoAim def only declares `shootAfter`, autos.js:41), so sim uses AUTOAIM_DEFAULTS.timeoutSec = 4 (autoaim_cmd.js:30). Java reads `a.seconds` (autoexport.js ~321) and otherwise uses TIMEOUT_S = 3 per the failing parity test. Two bugs: field names differ (`timeout` vs `seconds`), and default values differ (4 vs 3).
9. Timed markers on a path: sim runs timed commands (shoot, shootAll marked TIMED) as parallel branches at marker t (autos.js ~line 466-470). Java drops them with a `// TODO` comment (autoexport.js ~256) and does not run them. Divergence.
10. Marker node types other than command/sequential/parallel: sim runs them; Java emits TODO. Divergence (minor, validator should block).
11. shootAll: sim completes on hopperEmpty() or 6 s (autorunner.js:183). Java handling of shootAll inside the state machine was not found by grep (only in TIMED and KNOWN_COMMANDS). UNVERIFIED.
12. Errors: sim aborts the whole auto on any command exception (autorunner.js:24, _tick). No equivalent check was found in the Java generator. UNVERIFIED.
13. Path callbacks: Pedro 2.1.0 callbacks never fire (per OVERNIGHT_RULES). Java polls marker chain index and t, sim uses progress(); both are fine, but the Java path is not tested against real Pedro here.
