# t02: Audit exporter emitted code vs TeamCode (read-only)

Scope: `field_sim/web/js/autoexport.js` (statemachine + ivy styles) vs `TeamCode/src/main/java/commands/autonomous/*` and `TeamCode/src/main/java/robot/Robot.java`. No files edited. No gradlew, no git writes, no node tests run.

## Verdict
- Statemachine style: no missing symbols. Every robot/Pedro symbol it emits exists (table below).
- Structure matches the demo autos in the places that matter (base class, annotation, package, imports, Robot ctor, try/finally stop, update/addTelemetry loop, followPath/isBusyOrTimeout pattern).
- Two real defects found, both in naming (see "Defects"). Neither is a missing API symbol.
- Ivy style is not compile-ready: Ivy is absent from the Gradle cache (only com.pedropathing core/ftc/telemetry are present) and its names are marked UNVERIFIED in the exporter.

## Structure: exported statemachine vs demo autos
Same as demos:
- `extends LinearOpMode`, `@Autonomous(name=..., group=...)`, package `commands.autonomous` (default at autoexport.js:433). Demos: ShootWhileDrivingDemoAuto.java:1,20-21; AutoAimDemoAuto.java:1,16-17.
- Imports match the demos: `com.pedropathing.geometry.Pose`, `com.pedropathing.paths.PathChain`, `com.qualcomm.robotcore.eventloop.opmode.{Autonomous,LinearOpMode}`, `com.qualcomm.robotcore.util.ElapsedTime`, `robot.Robot` (autoexport.js:440). Demos use the same (ShootWhileDrivingDemoAuto.java:3-10).
- `new Robot(hardwareMap, pose)`, then `waitForStart()`, `try { ... } finally { robot.stop(); }`, `robot.update()` + `robot.addTelemetry(telemetry)` per loop (autoexport.js:479-489; ShootWhileDrivingDemoAuto.java:43-49, 85-87).
- Follow pattern `followPath(chain, true, timeout)` then `isBusyOrTimeout()` / `timedOut()` / `cancelMove()` (autoexport.js:308; ShootWhileDrivingDemoAuto.java:60-69).

Different (by design):
- Demos are blocking procedural loops (`while (opModeIsActive() && robot.auto.isBusyOrTimeout())`). The exporter emits a per-tick state machine (run/cancel methods, autoexport.js:289-384) so parallel/race/deadline can work. No TeamCode demo uses this shape; it is new code the team has not run.
- Alliance: demos never set it (they rely on Robot.ALLIANCE default BLUE, Robot.java:64). The exporter writes `Robot.ALLIANCE = Alliance.RED/BLUE;` before constructing Robot (autoexport.js:419-424). This works because the field is `public static` (Robot.java:64). `Robot.setAlliance` (Robot.java:296) also exists; not required.

## Defects (naming, compile-breaking)
1. Class names that clash with existing classes in the same package are not reserved. `sanitizeClassName` (autoexport.js:47-54) reserves only RESERVED_CLASS (autoexport.js:26). Existing files in `commands/autonomous/`: AutoAim, AutoAimLogic, AutoAimTunables, AutoDrivebase, AutoAimDemoAuto, ProfileDemoAuto, ShootWhileDrivingDemoAuto. An auto named "AutoAim" gives `public class AutoAim` in package `commands.autonomous`, which duplicates AutoAim.java. A name "AutoAimLogic" also clashes with the import at autoexport.js:124.
   - Aggravating: the download file name is built without the sanitizer. autoui.js:889 uses `cls = name.replace(/[^A-Za-z0-9_]/g,'')`, so "AutoAim" downloads `AutoAim.java`. Copying that file over TeamCode's AutoAim.java would overwrite the real class used by AutoAimDemoAuto.
2. File name and class name can differ. For a name starting with a digit (e.g. "1st Auto"), autoui.js:889 gives `1stAuto.java`, but sanitizeClassName (autoexport.js:51) gives class `Auto_1stAuto`. A public class in the wrong file will not compile.

Suggested fix (for the exporter owner, not edited here): add the 7 names above to RESERVED_CLASS (or suffix on collision with a known list), and make autoui.js:889 and app.js:695 use the same sanitized name for the file and the class. Test file to extend: field_sim/tests_js/autoexport.test.mjs (not run).
