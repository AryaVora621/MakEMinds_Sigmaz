## 2. Proposal
2a. hivecycle.js:220: `this.onTip(stateName, this.scored.length, lowered)`. Hoist `lowered` out of the `releaseOnTip` branch. Backward compatible.

2b. Wiring (app.js, not owned here): `hive.onTip = (st, n, low) => world.queueDrop(name, low, st === 'far_up' ? +1 : -1)`.

2c. balls.js new `queueDrop()` pushes to `this._drops`. At the start of `step(dt)` (before 428), for each drop:
```
w = sign * 1.5 * (60*RAD) / animationDuration      // smoothstep peak rad/s, DERIVED, ASSUMED use
for b of balls where state==='scored' && hive===hv && cell===drop.cell:
  rY = b.y - pivot[1]; rZ = b.z - pivot[2]
  release(b, [0, -w*rZ, w*rY])                     // line 338, omega x r
  b.shot = true                                    // no roller reload (INTAKE skip at 581)
  b.start = false                                  // no rest-capture (767)
  b._released = {hv, cell, until: t + COOL}
  if (!b._relCounted) { removeHiveBall(hv, kind); b._relCounted = true }
  depenetrate(b, hv)                               // 2d
```
Position is b.x/y/z from line 465, so there is no teleport. `_drops` is cleared after use.

2d. New `depenetrate(b, hv)`: while `hv.mesh.sphereContacts` (751) reports overlap, move along the opening normal (`co.sensor.n`) in 0.1 in steps, max 2 in. If still overlapping, zero the velocity and let it fall.

2e. New `_exiting(hv, p, q, r)`: mirror of `crossesGrownOpening` (99-108) with the sign reversed, active only while `b._released`. Exempt it from the mesh block in `_hiveSweep` (726) and `_hiveCollide` (748), alongside `entering`.

2f. New `removeHiveBall(hiveId, kind)` next to `recordHiveBall` (133). Clamp at 0. Called once per ball (`_relCounted` guard). DECIDED (ASSUMED): decrement, because a ball that falls out is no longer in the hive. This breaks the monotone comment at 129-130, which must be updated. Consumers of `hiveBallCounts` were not checked (unverified).

2g. Re-capture cooldown: skip `_enter` at 736 and `_hiveCapture` (757-772) while `b._released` is active. Clear it when `until` passes (COOL = 1.5 s, ASSUMED) or the centre is more than hv.R + 2 in from the pivot.

2h. Unchanged: MAX_HELD = 4 (90) and the held check (582). weightThreshold = 8 (hivecycle 57, hivetip_model). Counting rule (180). Released balls go to free, never held.

## 3. Risks and mitigations
1. Overlap explosion: scored balls ignore the mesh, so at settle a ball can sit deep in the lid. `_hiveCollide` then gives a huge penetration impulse. Mitigation: 2d, and clamp to BALL.maxSpeed (71).
2. Mesh traps the ball at the opening (726, 748). Mitigation: 2e.
3. Re-capture on the way out: a bounce re-crossing the opening sets `_enter` (736) and captures (765). Mitigation: 2g. Test: no capture of a released ball within COOL.
4. Double or missing decrement. Mitigation: `_relCounted`. `reset()` (254) clears the map.
5. Store divergence: lowered cell is passed once (2a), and the count list is untouched because post-tip counts are false.
6. Second tip inside COOL: drops are per cell. The new up cell is the other cell, so the exemptions do not collide. Unverified in sim.
7. Intake reload: `b.shot = true` (2c). Hold limit (582) still caps at 4.
8. Drop speed is not measured. At r = 10 in the kick is about 26 in/s. Smoothstep speed is zero at settle, so this kick is a modelling choice. Alternative: release mid-animation (more risk, needs a per-frame hook).
9. Conflict with hivecycle.js header line 21 ("balls are not removed by a tip"). That line cites the manual; the drop-out is the user's observation and is not in the manual. Record it as a user decision, and do not cite the manual for it.
