# t04: hivecycle.js tip and releaseOnTip audit (read-only)

Ran: read web/js/hivecycle.js in full (264 lines); grep of web/js for consumers; read app.js 302-312, 425-446, 562-573, 1036-1040, 1114-1127; read balls.js 390-422, 440-468. Nothing executed, no tests run, no files edited except this one.

## Storage
- The only ball store is `this.scored` (L91 reset to []; L122 push). Entry = {cell, type, counts, local}.
- `counts` is true only for a ball added to the up cell while at rest (L180). Starting nectar is stored with counts=false (L98).
- `local` is the body-frame position (L121-122), so stored balls rotate with the hive. `torqueBalls` (L195) is informational only.

## Tip path
- `_settleAt` (L207-222): L213 sets counts=false on ALL balls, whatever cell they are in. No ball is moved or removed by default.
- Stored balls keep their cell name, so the ball set that was in the old up cell is now in the down cell. It stays stored with counts=false.
- L216-219 (releaseOnTip only): `lowered` = 'audience' when far_up, 'far' when audience_up (L217, correct). L218 filters out every record in that cell and reassigns `this.scored` to a new array.
- L220 calls onTip(state, this.scored.length), so the count is post-release.
- Default releaseOnTip=false (L59). app.js:286 spreads HIVE_PARAMS and sets no override. No UI sets it (comment at app.js:286).

## Q1: does a ball in the new down cell stay stored forever?
Yes, by default. It stays in `this.scored` with counts=false and keeps counting in scoredInCell (L248). Only two code paths delete records: reset() (L91) and releaseOnTip (L218). Nothing else deletes.

## Q2: what releaseOnTip=true does
- It drops the records silently. Nothing is returned to balls.js: there is no callback and no ball list passed out (L220 passes a count only).
- The count in onTip is post-release, so app.js:444 ("N balls scored") undercounts.
- `_scoredTotal` (L184) is never decremented, so cycleStats().scoredTotal (L258) exceeds scored.length after a release.
- balls.js is a separate store. Captured balls stay in world.balls with state 'scored' (balls.js:417-419), are re-placed every substep (balls.js:465), and keep rendering. With releaseOnTip=true the model and the physics world disagree: the balls remain visible but are no longer in the tip model (ghost stuck). Latent only, because the default is false.

## Q3: ghost paths
1. Model-only records with no physics ball (ghost in the model): balls.js:410-413 caps each cell at `_cellCapacity` (balls.js:394-397). When full, the oldest scored ball is spliced out of world.balls. hivecycle has no cap (L122), so its record stays with counts possibly true. Tip counting and the screen then diverge. The comment at balls.js:410 says the hive's bookkeeping already counted the ball, but the hivecycle copy is still there.
2. Physics-only balls with no model record: UNVERIFIED. Starting nectar is in hivecycle (L98). Whether balls.js also spawns those 3 balls (balls.js:260 mentions "start balls (hive preloads)") was not checked.
3. Reset: hiveDyn.reset (L86-99) clears `scored`. resetHiveDynamics (app.js:566-573) then calls syncBallMeshes (app.js:302-312), which removes meshes only for ids no longer in world.balls. The AutoRunner reset hook (app.js:658) calls resetHives only. Whether world.balls is cleared on that path was NOT verified.
4. releaseOnTip=true: see Q2. Records vanish from the model while the balls stay on screen.

## Issue for lead: the new up cell is not physically empty
- L41 says "the new up cell starts empty", and L213 zeroes counts. But balls never leave a cell (L21), so the new up cell still holds all balls that were stored in it before (starting nectar plus earlier pollen).
- Those balls are uncounted. Tip progress restarts at zero even though the cell is physically full.
- app.js:1038 scores the end-of-match up cell from cycleStats().upCellCount (counted balls only). The header (L18-19) cites Table 10-2 for 2 points per ball left in the up cell, so uncounted balls in the up cell are not scored. This is a rule gap, not a crash. Decision needed (ASSUMED, not in the manual).
