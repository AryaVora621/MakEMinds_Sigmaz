# t05: balls.js capture path audit (read-only)

Source read: `web/js/balls.js` (lines 80-200 for constants/prepCell, 300-773 for BallWorld). Nothing was run; this is code reading only.

## How a ball becomes "scored"
- Entry: `_hiveSweep` (711-737) sets `b._enter = hive:cell` when the centre crosses the opening plane (`crossesOpening`, or `crossesGrownOpening` while `_entering`, 700-710). `_entering` (700-710) also stops the lip/rim from bouncing the ball (`_hiveCollide` returns early at 748).
- Capture: `_substep` calls `_hiveCapture` (532) for each free ball. `_hiveCapture` (757-772) requires the centre to be inside the cell sensor (`insideCell`, 764) and then either:
  1. `b._enter` already equals this cell (it crossed the mouth) -> `_capture` immediately (765), or
  2. `b.start` (hive preload) and slow (`captureSlow`) for `BALL.captureRest` seconds (767). Non-start balls that rest inside without crossing never capture (768-769).
- Constants `BALL.captureRest`, `BALL.captureSlow`, `ENTRY_DEPTH=3` (96) are defined outside the read range; values not checked.

## What `_capture` does (405-422)
- Picks the lowest free slot index `k` not used by a scored ball in the same hive+cell (407-408).
- If `k >= _cellCapacity` (396: floor(width/3.62) * floor(floorLen/3.62) * 3), the oldest scored ball (lowest `_seq`) is removed from `this.balls` silently (410-413) and its slot is reused. It is not released.
- Sets `state='scored'`, `hive`, `cell`, `_slot`, zeroes velocity (417-418), stores local CAD coords `_lx/_ly/_lz` (418), calls `_placeScored` (419), `_wakeAbove` (420), and queues `_pending` (421).
- `_pending` is flushed at the end of `step()` (466-468): `recordHiveBall` (monotone counter, 133) and `onCapture(b, hive, cell, _captureInfo)` (400-404).

## Position: slot grid, not physical settling
- `_slotPos` (380-389) is deterministic: column from x-span / 3.62 (381-384), row along the floor from `floorU`, layer along `floorN` (385-387). No gravity, no contact, no settling.
- `_placeScored` (390-393) rotates `(_ly,_lz)` about the hive pivot (x-axis, `hv.delta`) and keeps `x = _lx`.

## Is a scored ball simulated?
- No. `_substep` skips every non-free ball (496: `if (b.state !== 'free') continue;`). Scored balls get no integration, no gravity, no wall/hive/robot contact, and are not in `list` for `_ballBall` (492-512, 542+).
- Each `step()` re-places them after `hv.delta = hv.d1` (464-465). So they are kinematic: fixed in the hive frame and rigidly rotated with it. They do follow hive rotation.
- Side effect: free balls pass through scored balls (no collision with the stored stack).

## What would make a ball fall out when its cell faces down (not implemented)
Nothing in the code currently releases a scored ball. Needed changes (all in `balls.js`):
1. Per step, after the placement loop (465), test each scored ball's cell: rotate the cell's opening normal (`co.sensor.n`, or `pc.floorN`) by `hv.delta` and check its world z (or check the slot's world z vs pivot). Threshold is a design decision (TODO).
2. For balls past the threshold, call `release(b, vel)` (338-341). Velocity: `[0, -hv.omega*rdz, hv.omega*rdy]` as in lines 733 and 754. `release` does not call `_wakeAbove`; add it, or balls above will float.
3. Stop re-capture: `_hiveCapture` (765) would re-capture a released ball lying in the cell if `_enter` still matches. Clear `_enter` on release (done at 339) and avoid `b.start` resting capture (767) for released balls.
4. Score: `recordHiveBall` (466) is monotone, so releasing a ball does not reduce the reported score. Decide whether a fallen ball should decrement (currently: not decremented, and the ball is no longer counted in `stats().scoredRed/Blue`, 352-356).
5. Free-ball/hive geometry: a released ball is inside the mesh cell. Whether it exits through the mouth depends on `hivemesh.js` (not read here) and on `_hiveCollide`/`_hiveSweep` (742-756, 711-737) keeping it inside when the mouth is down. This needs a physics test on the 3D sim (not run).
