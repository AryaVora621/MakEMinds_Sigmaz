# t08: Audit of hivetip_model.js and the tip threshold

Lead: hive-physics. Worker: Haiku t08. Scope: read-only audit, no source edited.

## Constants (verified by reading web/js/hivetip_model.js)
- HIVE_TIP.threshold = 8 (line ~70). Ledger tags it user-authoritative, not in manual.
- HIVE_TIP.pollenWeight = 1 (ASSUMED unit scale).
- HIVE_TIP.nectarWeight = 1.75 (INFERRED, range 1.75..2.0, Chief Delphi 14343 table).
- shouldTip = tipWeight >= threshold - 1e-9. tipWeight = pollen*1 + nectar*1.75 (counts floored, clamped at 0).

## Edge cases (computed with node: shouldTip / tipWeight)
| Input | Weight | Tips? |
|---|---|---|
| exactly 8 pollen | 8.00 | yes |
| 7 pollen | 7.00 | no |
| 7 pollen + 1 nectar | 8.75 | yes |
| 4 nectar | 7.00 | no |
| 5 nectar | 8.75 | yes |
| 3 starting nectar, 0 scored | 5.25 (stored, not counted) | no (see note) |
| 4 pollen + 2 nectar | 7.50 | no |
| 4 pollen + 3 nectar | 9.25 | yes |
| 3 nectar + 3 pollen | 8.25 | yes |

Starting nectar: hivecycle.js line 98 stores them with counts=false, and _upCounts() skips counts=false, so they are excluded. Verified in code. The hivetip_model_test 'nectarToTip' gives ceil(8/1.75) = 5, consistent with the table.

## Consistency check
- hivetip_model.js vs hivecycle.js HIVE_PARAMS: consistent. ballsToTip = 8, nectarWeight = HIVE_TIP.nectarWeight, tipWeightThreshold = HIVE_TIP.threshold, mode 'weight'. _shouldTip() delegates to modelShouldTip with the same weights.
- balls.js tipReady(counts) = shouldTip(counts) using default HIVE_TIP. Consistent with the model. No separate threshold in balls.js.
- Gap: hivecycle tipWeightThreshold and nectarWeight can be overridden via setRule/params, but balls.js tipReady always uses HIVE_TIP. Not a bug today (tipReady is only called by tests in tests_js/ballkinds_*.test.mjs; no web/js caller found), but the two paths can disagree if a caller overrides hive params.
- Gap: addScoredBall only tips when counts && !moving, so a ball landing mid-animation never counts. This matches the tests.

## Stale comments (no logic impact, but misleading)
- hivetip_model.js lines ~25-42: the header ledger still uses 1.6545 (AndyMark ratio). Its worked examples (4p+1n = 5.65, 4p+2n = 7.31, 4p+3n = 8.96) and nectarToTip = 5 derivation use 1.6545, not the 1.75 in HIVE_TIP. Line 72 comment states 1.75 is used. The SOURCE.nectarWeight string also says "ASSUMED proportional to mass" for 1.75.
- hivetip_model.js line 63 note: 'nectarToTip = ceil(8 / 1.6545) = 5' (value still 5 with 1.75, so the number is right but the cited weight is wrong).
- hivetip_mixed.test.mjs header (line ~5-8) says nectar weight 0.091/0.055 is used. It is not; HIVE_TIP.nectarWeight = 1.75.
- tests_js/ballkinds_shootfix.test.mjs line 78-83 and tests_js/ballkinds_mixed.test.mjs line 26 comment with 1.654 / 1.6545. Assertions still pass with 1.75 (checked the table above), but the comments give the wrong weight.
- hivecycle.js line 32 comment is correct (1.75).
