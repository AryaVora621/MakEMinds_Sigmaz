## Interaction: tip, up-cell and removal
1. **Tip resets the up-cell count.** `_settleAt` sets `counts=false` on every scored ball (hivecycle.js:213), so balls counted toward a tip are not in the new up cell. `_upCount()` (134) only sees counted balls, so a double count across tips does not happen.
2. **Tip is detected at settle.** `onTip` fires only when `_settleAt` runs with `natural` true (hivecycle.js:209-221), and `scorer.onTip` runs off that. A tip is counted once.
3. **Mid-tip finalize is wrong (edge).** `addScoredBall` (hivecycle.js:179-187) starts the tip animation via `_startAnim`, but `counts` stays true until `_settleAt` (0.6 s later, `animationDuration`, hivecycle.js:60). If the match ends in that window, `finalize` (app.js:1038) reads `upCellCount` with the tipping balls still counted. Those balls are now in the lowered cell, so they should score 0 up-cell points but score 2 each. `finalize` does not check `moving`. Not run; from code reading only.
4. **No match-over gate on tips.** `simUpdate` finalizes once (app.js:1036-1037), but `onTip` still calls `scorer.onTip` afterwards (app.js:441-443). `summary()` recomputes totals from `s` (matchrules.js:162-166), so a late tip changes the total after finalize. Shooting after 'over' is not checked in this audit.
5. **Starting nectar.** `reset()` stores 3 nectar with `counts=false` (hivecycle.js:94-101, startingNectar 3 at hivecycle.js:57). Not counted, as the comment says.

## Ball exit / stale counts
- **No ball leaves a hive physically today.** Scored balls are kinematic and never released (balls.js: `_substep` skips non-free balls; per the t05 audit). `releaseOnTip` is false (hivecycle.js:59), so the lowered-cell list is not pruned (hivecycle.js:216-218). No double count from a tipped ball: its `counts` is cleared at settle, and it is not in the up cell.
- **HIVE_BALL_COUNTS is not used for scoring.** The only readers are `hiveBallCounts` tests and `tipReady` tests (tests_js/ballkinds_*.test.mjs). The live tip and up-cell path uses `HiveDynamics` (`_shouldTip`, hivecycle.js:146-152), not `tipReady`. A future change that reads `HIVE_BALL_COUNTS` for score would be monotone (balls.js:129-130) and would not drop when a ball is released or recycled. It would overcount.
- **Recycled balls stay counted in hiveDyn.** When a full cell recycles its oldest ball (balls.js:410-413), the ball is removed from `world.balls` but not from `hiveDyn.scored`. If that ball had `counts=true`, the up-cell count stays high. Only reachable when a cell is over capacity (`_cellCapacity`, balls.js:396) before a tip. Low risk with the 8-ball weight tip.
- **Two tip models.** `HiveDynamics` uses `hivetip_model` in weight mode (hivecycle.js:146-152, mode 'weight' at hivecycle.js:53). `tipReady` / `shouldTip` (balls.js:145-146) is a separate path with no live caller. The two agree only if both use the same weights.
