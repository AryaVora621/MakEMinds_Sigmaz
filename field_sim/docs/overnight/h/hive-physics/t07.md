# t07: hive collision geometry audit (read-only)

Scope: web/js/collision.js (156 lines), web/js/balls.js (hive/substep paths), web/js/hivemesh.js (used by balls.js). Nothing edited. No git write commands.

## 1. What collides with what
- collision.js (robot vs field): only ROBOT box (halfX 9, halfY 9, line 3), AABB boxes (lines 7-20, 102-109), circles, play bounds. It has no hive mesh code. Whether colliders.json includes hive boxes: unverified (not read).
- balls.js ball vs hive: hive is a triangle mesh (double-sided) in the hive LOCAL frame (world minus pivot, CAD pose). Source: web/data/hive_collider.bin (app.js:290-291), else buildFallbackMesh (balls.js:229, hivemesh.js:265-286).
  - Fallback mesh per cell: floor quad, back wall quad, lid quad, two side plates, two gable shoulder tris in the opening plane (hivemesh.js:273-282).
- Cell sensors (capture volumes): convex prisms from cellSensors (hivemesh.js:204-231), inset 0.5 in (SENSOR_INSET) and 1.0 in behind the opening (OPEN_INSET). Used only for capture, not for solid contact.

## 2. Static or rotated with tip angle?
- Mesh and sensors are STATIC in the CAD local frame. Rotation is applied to the ball instead: _loc() maps world to local with -delta (balls.js:692-695) and _toWorld() maps back (balls.js:738-741). delta = (angle - cad) in radians (balls.js:431, 464).
- Tip angle is per-substep interpolated: hv.delta = d0 + (d1-d0)*(k+1)/n (balls.js:450). Contact velocity from hive rotation: -omega*rdz, omega*rdy (balls.js:733, 754). Correct in principle, verified by reading only.
- Hive bounding radius hv.R = max corner distance + 4 in (balls.js:225-234). Ball skipped if outside R (balls.js:714, 745).

## 3. Tunnelling
- FIXED_HZ 240, so h = 1/240 s = 4.17 ms (balls.js:201, 474). maxSubstep 0.004 s (balls.js:67) gives n >= 2 per fixed step (balls.js:447).
- Substep count n = min(120, max(1, ceil(dt/maxSubstep), ceil(dt*vmax/maxStepTravel))), maxStepTravel 0.8 in (balls.js:69, 447). vmax includes hive omega*R and robot speed (balls.js:428, 436, 445).
- Worst case with BALL.maxSpeed 1800 in/s (balls.js:71, clamp at 506): dt*vmax/0.8 = 0.00417*1800/0.8 = 9.4, so n = 10 and travel per substep is 0.75 in. Pollen r 1.4, nectar r 1.8 (radii from BALL_KINDS). Travel per substep is under one radius.
- Hive uses a segment sweep (_hiveSweep, balls.js:711-737, sweepSegment in hivemesh.js:154-188). Thin walls are not skipped by the sweep. Rim contact uses sphereContacts (hivemesh.js:108-139), which is penetration-based.
- Robot: pose interpolated across substeps only when robot moves < 40 in per fixed step (balls.js:445). Above that the robot teleports; a fast robot can pass through balls. Unverified in practice.
- Caveat: step(dt) clamps dt to 0.1 and caps n at 120 (balls.js:426, 447). Under stepFixed (always h = 1/240) the cap is not reached. Only a direct step() call with a large dt could exceed 0.8 in per substep.
- Conclusion: no tunnelling expected at the 1800 in/s clamp. Not verified with a test.

## 4. Gaps that could stop a ball leaving a cell opening
Code-level:
- A. Entry exemption can skip ALL mesh contacts. _hiveCollide returns early when _entering() is true (balls.js:748). _hiveSweep skips the blocking test when entering (balls.js:726). _entering covers centres from 3 in behind to 2r+1 in front of the opening plane, and within r of the opening polygon (balls.js:700-710). A ball centre just outside a side plate edge (within r of the polygon edge, and up to 3 in behind the plane) gets no side-plate contact. This is a possible leak through the side edge into the cell. Not confirmed; needs a sim test.
- B. Rim contacts still apply to exiting balls. _entering is false when the ball moves out (dQ >= dP), so the rim and solid mesh act. Exit is blocked only if the rim pushes the centre back in (normal toward the cell). Depends on the CAD rim triangles below.
- C. Fallback mesh only: the gable shoulder triangles (hivemesh.js:282) are in the opening plane at the top corners. By geometry (not computed) they should lie outside the pentagon, so the fallback should leave the opening open. Unverified by test.

Data-level (hive_collider.bin, from a node run, see section 5):
- D. The CAD mesh has 97 triangles lying in the opening plane of each cell (red audience, and each other cell, same count). Most sit on the bottom edge (about 0.3 to 1.6 in below the bottom edge) and the gable apex (about 13.5 to 14.3 in). These are lip/rim triangles. A ball leaving through the bottom lip meets them.
- E. One in-plane CAD triangle (about 0.5 in across) has its centroid inside the pentagon for red audience cell (run 1). Its exact 2D position was not confirmed. If it sits in the exit path, it can block a ball. Needs a visual or physics check.
- F. Ball-sized clearance: pentagon width 20.04 in; the widest ball diameter is 3.6 in (nectar). Width is not the issue; the lip triangles and point E are the candidates.
