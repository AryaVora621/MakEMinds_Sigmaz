# t15: 3D rendering of balls in the hive (audit, read-only)

Scope: read-only audit of web/js/app.js, web/js/balls.js, web/js/hivecycle.js. Nothing was edited or run. No tests, no browser, no screenshot. Everything below is from reading the code.

## Two parallel stores, two frames

1. **Rendered store: balls.js `world.balls`, WORLD coordinates.**
   - Free balls: `b.x,b.y,b.z` are world (Pedro inches, balls.js:2).
   - Scored balls: stored in the hive-local frame as `b._lx,_ly,_lz` (balls.js:418), then projected to world by `_placeScored` (balls.js:390-393) using the live tip angle `hv.delta` (balls.js:391-392). It runs at the end of every step (balls.js:465) and again after each capture (balls.js:419).
   - Rotation is about +x through the pivot, same as `group.rotation.x` (balls.js:8-10).
2. **Bookkeeping store: hivecycle.js `this.scored`, HIVE-BODY LOCAL coords.**
   - `_store` takes the world point, subtracts the pivot, and rotates by `-theta` into the body frame at angle 0 (hivecycle.js:116-123). Each entry is `{cell,type,counts,local:[y,z]}` (hivecycle.js:47-48).
   - It is never rendered. It only drives tip counting and `torqueBalls`.
   - Its frame (angle 0, neutral) differs from balls.js's frame (CAD pose, `delta = angle - cad`, balls.js:274). The two are not shared and do not need to be; each is internally consistent. Nothing converts between them.
   - Feed: app.js:433-434 `world.onCapture` calls `hiveDyn[alliance].addScoredBall(cell, [ball.x,ball.y,ball.z], type)` with the ball's world position.

Consistency today: a scored ball is rigid in the hive. Its world position is recomputed from `hv.delta` every step, so it tips with the hive (balls.js:465). Good for "balls ride the hive". It is also the reason they never fall.

## Rendering path

- app.js:297-311 `ballGroup` lives at the scene root, NOT under `hive[a].group`. `syncBallMeshes` sets each mesh to `b.x,b.y,b.z` world (app.js:309). Meshes are hidden when `state === 'held'` (app.js:308).
- `syncBallMeshes` runs every frame from `updateBalls` (app.js:457). Released balls need no extra render code: any ball that becomes `free` in `world.balls` is drawn automatically.
- app.js:170 hides the static CAD scoring balls (`category` starts with `scoring_`) so only physics balls show.
- Hive angle reaches physics via `world.setHiveAngles` (app.js:451) using `hive[a].shown`, which comes from `hiveDyn[a].angleDeg` (app.js:1061). That is the animated tip angle.

## Why balls never drop out today

- `releaseOnTip` defaults to `false` (hivecycle.js:59). Even when true, `_settleAt` only filters the `hiveDyn` array (hivecycle.js:216-219). It never touches `world.balls`.
- `onTip` handler (app.js:440-446) only updates state, aim marks, toasts and `scorer.onTip`. It does not call `world.release` or change any ball's state.
- The only caller of `world.release` is flowerarm.js:121, for held balls. No code path moves a `scored` ball to `free`.
- Net effect: after a tip, scored balls stay in the hive frame and rotate with it. Nothing falls, and the rendered stack just rotates.

## Render/physics changes needed so released balls visibly fall

Minimal set, in order:

1. **Choose the release set on tip.** On `_settleAt` with `natural` (hivecycle.js:214), pick the scored balls whose cell is now down, or whatever rule is decided. Expose it through `onTip` or a new hook. Keep `hivecycle.js` counting unchanged.
2. **Convert those balls to free in balls.js.** Use the existing `release(b, vel)` (balls.js:338-339). Set `b.state='free'`, clear `hive`/`cell`/`_slot`, and set `sleeping=false`. Pass the current world position, so the first frame is continuous. Pass the tip angular velocity as `vel` (`hv.omega * R` at the ball, balls.js:733 pattern) so they leave the hive.
3. **Keep the position continuous.** `release` keeps `b.x,y,z`. `step()` must stop calling `_placeScored` for them (balls.js:465 filters on `state==='scored'`, so this happens automatically once the state changes).
4. **Keep counts consistent.** `_captureInfo` totals and `_cellCapacity` slot logic (balls.js:402, 407-413) count `scored` balls. Released balls leave those counts. Decide whether the hive's displayed count should drop. This is a gameplay decision, not a render one.
5. **app.js: no render change required.** `syncBallMeshes` already draws any `free` ball at its world position. Optionally, call `syncBallMeshes` right after the tip event so the first frame is not stale.
6. **Sync hivecycle.** Remove the same balls from `hiveDyn.scored` (hivecycle.js:216-218 does this for `releaseOnTip`). Otherwise the bookkeeping will count balls that the physics world no longer holds.
