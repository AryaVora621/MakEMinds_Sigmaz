# t04 - solveAuto solver stability audit (read-only)

Scope: web/js/shot_core.js (Core.solve, quarticPosRoots, cubicRealRoots, minSpeedT, finish, forward) and web/js/shotrules.js (solveAuto, ranges, stationaryOk, rangeKey, solveAutoShot, maxRangeEstimate, nearestRangeEstimate, autoPhysics, evaluateShot auto path, feasibleRegion).

## What was run vs read
- READ: both files in full. Algebra checked by hand: theta quartic coefficients, speed quartic, minSpeedT derivation, forward() landing identity, kinematics vs. forwardShot robot-velocity term.
- RAN: a scratch Node probe in the scratchpad (not in the project). Loaded shot_core.js as a classic script, then called solveAutoShot / maxRangeEstimate. Geometry was ASSUMED for the probe only (exit 20 in, target z 40 in, hood 20..60 deg, wheelR 2, eff 0.45, maxRpm 6000, pivot 0). Not robot constants.
  - d sweep 30..90 in, step 0.25: no rpm jump >80 or gamma jump >3 deg. The hood-clamp branch (shotrules.js:189) was not clearly exercised by this sweep.
  - maxRangeEstimate(pivotY=0) and (pivotY=10) with the same target returned the identical 792.70 (see F1).
  - maxRpm=1 gave far = NaN (see F5).
- NOT RUN: no physics sim, no browser, no test suite, no solver-vs-flight() comparison over a grid.

## Verdict
For the auto path with finite, valid inputs, the solver does not return NaN or Inf. Closed-form landing is exact by construction. The real problems are: a stale range cache, a pose-vs-pivot distance mismatch, a silent solution switch at the hood clamp, and tangency-driven root-count jumps. None of these were seen in the single probe geometry.

## Findings (file:line)

F1 [bug, cache] shotrules.js:203 rangeKey omits sh.pivotX and sh.pivotY, but solveAuto reads them (shotrules.js:185, rx/ry). Changing the pivot returns stale ranges. Probe: pivotY 0 and 10 gave the same 792.70 (the second call hit the cache; uncached pivot=10 value was not computed). Fix: add pivotX, pivotY to the key.

F2 [inconsistent reference] ranges() scans a stationary pose at x = tg.x - d (shotrules.js:206, h=0), so `d` is pose-to-target. autoPhysics computes d from the pivot (shotrules.js:250-251). With a pivot offset, the "too far / too close" messages and HOOD/RPM range hints (254-262, 297-298) compare different distances. Magnitude = pivot offset; not measured.

F3 [discontinuity] shotrules.js:186-189: gamma solve (entry = entryDeg) is replaced by theta solve at the clamped hood angle whenever the gamma elevation is outside [hoodMin, hoodMax]. Entry angle, T, rpm and turret all jump at that boundary. The switch has no continuity check. If the theta solve fails (r2.ok false), the gamma solution is kept with an out-of-limit elevation, which autoPhysics does catch (shotrules.js:260, HOOD_LIMIT). Not observed in the probe; boundary crossing needs a geometry that hits hoodMin/hoodMax.

F4 [root-count jumps, tangency] shot_core.js:52-72 (critical points + bracketing). Tangent double roots are kept only if |f(crit)| <= 1e-12*scale (line 70). Near the speed-minimum (speed mode) or the theta discriminant boundary, two roots merge and then vanish, so cand goes 2 -> 1 -> 0 with no continuity. At 2 -> 1 the branch selector (shot_core.js:169, cand.length===1 ignores branch) silently switches which arc is used. Relevant to 'speed' and 'theta' modes; solveAuto itself only uses gamma (unique) and theta (shotrules.js:189).

F5 [NaN by design, guarded] shotrules.js:222: when no feasible d exists, ranges returns {near: NaN, far: NaN}. Probe confirmed far = NaN at maxRpm=1. Internal guards (254-255, 261-262, 266-267, 297-298) use x === x checks, so they do not emit "NaN in". Callers of maxRangeEstimate/nearestRangeEstimate outside this file were not checked (unverified).

F6 [edge, not reachable on auto path] shot_core.js:107-113 finish: T = 0 gives uh and uz = Infinity. T = 0 is a root of the theta/speed quartic only when e = h^2 - tan^2(theta)*d^2 = 0. shotrules.js:157 removes T with 0.5GT^2 <= h (p.allow_rising is undefined in solveAuto, shotrules.js:184-185), so the auto path is protected. With allow_rising=true a near-zero T gives unbounded speed. minSpeedT (shot_core.js:76-87) with d=0 and h=0 returns T ~ 0, and uhm = D/Tm is 0/0 = NaN (shot_core.js:147; reached only from the speed branch).

F7 [minor throw] shot_core.js:150 calls param.toFixed(2) in the unreachable branch. Throws if speed param is undefined (NaN.toFixed does not throw).

F8 [convergence] No iterative robotVel compensation exists. shot_core.js:106 sets uh = D/T - vs, so vs+uh = D/T exactly. Verified algebraically: disc = uz^2 - 2Gh = (uz - GT)^2, so forward() (shot_core.js:20-28) returns the same T and err ~ 0 for any returned solution. Bisection caps (200 iters, lines 59, 81) are not binding: 40 to 60 halvings reach double precision. The velocity model ignores om during flight (constant pivot velocity assumed); that is a model limit, not a convergence issue.

F9 [kinematics consistency, OK] shotrules.js:149-150 (forwardShot) matches shot_core.js:15 (vs = v - om*rf): vx0 = vx - om*(py - pose.y) and vy0 = vy + om*(px - pose.x) are the same as the core formula with rf = pivot offset. Checked by hand; not run against a random sample.

F10 [range scan resolution] shotrules.js:216-221: 1-inch scan with MAXD = 1500. Feasible islands narrower than 1 in, or gaps inside [near, far], are invisible. If stationaryOk(1500) is true, far = 1500 and 1501 is never checked. Bisection (226, 229) is fine.

F11 [caller-supplied solution not re-checked] shotrules.js:367-374: evaluateShot auto mode uses ctx.sol without re-solving from the current pose or robotVel, and mutates it (rpm, turretDeg, fromBehind). A stale sol passes physics checks with the old geometry. Caller contract not checked.

F12 [silent config defaults] shot_core.js:174-175 (Rw||2, eta||0.45) and shotrules.js:133 (rpmScale||1). A missing or zero wheelR/eff silently uses 2 / 0.45, which masks bad config. eff = 0 gives rpm Infinity (blocked by RPM_TOO_HIGH, not NaN).

## Summary of risk
- Highest: F1 (stale cache, reproduced by probe), F3 (silent arc/entry switch at hood limits), F2 (distance reference mismatch).
- Medium: F4 (tangency root drops), F11 (stale ctx.sol accepted).
- Low: F5, F6, F7, F10, F12.
- No NaN/Inf reachable from valid auto inputs found by reading; the probe agreed (no NaN in the non-degenerate sweep).
