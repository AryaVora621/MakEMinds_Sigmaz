## Sampling and tunnelling
- Default step is time-based: dt = 0.002 s (shotrules.js:76), tMax 3 s. Each step tests a sphere of radius R = 1.391 in (BALL_R, :46; ball kind radius via opts.ballR) against boxes (:95-105).
- Measured with dt 0.002 and a launch at z=500 (no floor interference): a wall of thickness t is missed only from about v = 1600 in/s (t 0.01 and 0.05) or 1800 in/s (t 0.5). Analytic threshold (2R+t)/dt gives 1396, 1416, 1641 in/s. The sweep matched the formula.
- Nominal ball speed is at most about 534 in/s: wheel surface speed at maxRpm 6000, wheelR 1.89, eff 0.45 (app.js:32); nectar ball speed is scaled by launchScaleFor (about 0.78, balls.js:43-45). Margin is about 2.6x, so no tunnelling at current settings.
- Risk if dt is raised: with dt = 0.01 a 0.05 in wall is missed from about 320 in/s (measured). Any caller that overrides dt (landing() at :167 and autoPhysics at :272 use the default) must keep dt <= about 0.002 for shots up to 500 in/s. Recommend a hard assert or a swept-segment test (segment-vs-expanded-box) to remove the dependence.

## Ignore zone (main defect)
- flight() skips ALL obstacle tests while the ball is within ignoreStart (default 4 in, :77) of its start point (:90, far flag). Field-wall checks sit in the same branch (:92).
- Measured: a 0.1 in wall 1 in ahead of the exit at 300 in/s is NOT blocked; a wall 3 in ahead IS blocked. So any hive part within about 4 in of the exit is invisible to trajectoryBlocked and to the manual forward sim (landing() at :167 uses the default 4).
- Start embedded in an obstacle: blocked only if the ball is still inside a box after leaving the 4 in zone. A 10 in thick box containing the start blocks at 4.2 in (measured); a 6 in box containing the start does not block (measured). Result depends on depth, not on whether the ball is physically stuck.
- Whether any real hive geometry lies within 4 in of exitHeight/pivot: unverified (no measurement of geometry against the exit point was done).

## EXIT_BLOCK_IN = 24 in manual mode
- Definition shotrules.js:48; use shotrules.js:358-361. dd is the 3D distance from the forward exit point (fs.exit) to the first hit. dd <= 24 gives severity 'block'; otherwise 'warn'.
- Blocks are real only within 24 in. Hits beyond 24 in are allowed. This matches the header contract (shotrules.js:16-17: manual blocks only hard impossibilities) but 24 is not sourced: ASSUMED, no source in repo (grep found only the definition and the header comment). Mark TODO.
- Read-only finding: the 'warn' reason at :360 has no wouldBlock flag, and finish() only counts wouldBlock reasons in the summary (:329-330). Result: a ball that hits the frame 30 in away gives summary 'OK to shoot' and only the FORWARD_SIM line 'Ball would miss the opening' (:362). The driver is not told why. Suggest adding wouldBlock: true to that warn, or a distinct summary.
- The forward sim also stops at the target plane (:109-114). Hits after the plane are not counted, which is the intended behaviour.
- No test found for the 24 in boundary (grep of trajectoryBlocked shows only shotrules.test.mjs:101-110, which covers a leg hit, an open path and a field wall).

## Numeric edge cases
- Zero velocity: free air, not blocked (ran). Ball falls to the floor and the loop ends at :118. Start inside a box: see the ignore-zone section.
- Vertical shot (vx = vy = 0): ran, 800 in/s through a 0.05 in slab at z 100.3 is blocked; a roof box at z 30..31 is blocked. Fine.
- Opening normal degenerate case (read): landing() at :170-171 divides by hn = hypot(n0, n1) || 1. If the normal were vertical, lat = [0,0,0] and a = 0 always, so lands would be wrong. Not reachable with scene.json data (all normals have horizontal part 0.866).
- NaN velocity: ran, trajectoryBlocked returns blocked=false silently, because NaN comparisons at :90 and :92 are false so no test runs. False negative. Reachability from app inputs: unverified. Suggest a Number.isFinite guard that returns blocked (or an error reason).
- Target plane: if start is already behind the plane (prevS <= 0), cross is never set (:109). Read only, no run; acceptable.

## Other gaps

## Suggested follow-ups (owned by other workers; not edited here)

3. Manual warn beyond EXIT_BLOCK_IN: set wouldBlock so the summary names the frame hit. Mark 24 in as ASSUMED with TODO until a source is found.
