### Finding 1 (the only defect class seen): NaN returned by range estimators
Exact arguments: `SR.maxRangeEstimate(SH_LOW, target, undefined, 'nectar')` and `SR.nearestRangeEstimate(SH_LOW, target, undefined, 'nectar')`, where SH_LOW = SH with maxRpm 2400 and target = the hive aim point above.
- Both return NaN. Cause: shotrules.js `ranges()` sets `{near: NaN, far: NaN}` when `stationaryOk(d)` is false for every d in 1..1500.
- Verified with probe.mjs: 0 of 1500 integer distances pass for nectar at maxRpm 2400. For pollen at the same settings, 55 distances pass (d = 1..55).
- So this is a feasibility result (nectar cannot be made at 2400 rpm), returned as an undocumented NaN sentinel. `autoPhysics` guards with `rg.far === rg.far`, so the shot-rule path handles it. Callers that use the raw number may not.
- Not a crash. Classification: unhandled sentinel, a design question for the owner. Not a numerical solver bug.

### Other checks: clean
- solveAutoShot at the hive aim point (0 distance), at corners, and with 100 in/s robot velocity: no NaN, Infinity or throw. Failed solves return ok:false with a finite reason.
- evaluateShot: no non-finite fields in any result.
- feasibleRegion: no non-finite fields. Cell reason codes were collected but not inspected individually.
