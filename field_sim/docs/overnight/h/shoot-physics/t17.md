# t17: Scoring weights and hive tip audit (read-only)

Scope: read-only audit. Files read: hivetip_model.js, hivecycle.js, balls.js, app.js (capture hook, line 433-434), tests_js/hivetip_model.test.mjs, tests_js/hivetip_mixed.test.mjs, plus one grep of callers under web/. I did NOT run the node tests. Everything below is from reading code.
The 1.75 nectar weight is INFERRED (team 14343 table, see hivetip_model.js:20-24). It is not an official rule.

## Answers

1. Kind and count fed on capture: partly right.
   - Live path: balls.js:467 calls onCapture, and app.js:433-434 forwards it to `hiveDyn[alliance].addScoredBall(cell, pos, /nectar/.test(ball.type) ? 'nectar' : 'pollen')`.
   - The kind comes from the regex on `ball.type`, not from `ball.kind`. balls.js:121 `kindOf` prefers the explicit `kind`. The two disagree whenever `type` and `kind` diverge. Today they agree: scene types are `pollen`, `nectar_red`, `nectar_blue` (web/data/scene.json), and shots use `type = kind` (app.js:426, balls.js:332).
   - `recordHiveBall` / `hiveBallCounts` / `tipReady` (balls.js:133-146) are not on the live tip path. Within web/ they are only defined in balls.js. Only tests call them. The tip model does not read them.

2. Weight 1.75 applied consistently: yes on the live path, no in the tests and the source ledger.
   - Live: hivecycle.js:147-157 `_shouldTip` passes `nectarWeight: this.p.nectarWeight` (1.75 by default, hivecycle.js:56). `_weightOf` (hivecycle.js:125) and `torqueBalls` (hivecycle.js:195) use the same value.
   - `tipReady` (balls.js:146) and `shouldTip` default to HIVE_TIP (hivetip_model.js:70-77), so they ignore any `setRule()` change (hivecycle.js:170-176). It is inconsistent with the hive only if `setRule` is used.
   - Tests use HIVE_TIP, so they track the constant: hivetip_mixed.test.mjs:95 (`8 - 3*1.75 = 2.75 -> 3`) and :183 (`3 nectar = 5.25`) are correct for 1.75.
   - No test pins `nectarWeight === 1.75`. Changing the constant would not fail a test by itself, unless the derived counts (3n3p, nectarToTip) move.

3. Tipped hive: accepts and stores all shots. It never rejects.
   - `addScoredBall` (hivecycle.js:179-189) stores every ball. Balls into the down cell or mid-motion are stored with `counts=false`. They are never refused.
   - After a tip, `_settleAt` (hivecycle.js:213) sets every stored ball to `counts=false`. The new up cell starts empty (test (6), hivetip_mixed.test.mjs:161-179).
   - Design gap: a ball that lands in the new up cell during the 0.6 s swing (`animationDuration`, hivecycle.js:60) is stored but never counts toward the next tip. It sits physically in the up cell and is not counted by the model. This is the documented rule (hivecycle.js:39-41) and pinned by hivetip_mixed.test.mjs:141-158, but it is a physical/model mismatch. Flag it for the lead as a design decision, not a bug.
   - Physical cell recycling (balls.js:410-413) removes the oldest ball, but `HiveDynamics.scored` is never decremented, so the model keeps counting it. This is intentional for monotone counts (balls.js:129-130). Not verified against real cell capacity.

4. Hard-coded values that contradict the INFERRED label:
   - hivetip_model.js:60, `SOURCE.nectarWeight`, starts with "SOURCED" and cites the AndyMark mass ratio (0.091/0.055 = 1.6545). The value in use is 1.75, not 1.6545. The string attributes the weight to a source that does not produce it. The word INFERRED appears nowhere in the SOURCE block. It is only in the header (hivetip_model.js:20) and the HIVE_TIP comment (hivetip_model.js:72).
   - hivetip_model.js:63 note: `nectarToTip = ceil(8 / 1.6545) = 5`. The live value is ceil(8/1.75) = 5 (same result, different stated basis).
   - hivetip_model.js:129 `hivePolicyFromParams` gives pollen-only `ballsToTip`. Not a contradiction, but a second tip rule for `mode: 'count'`, which counts nectar as 1 ball (hivecycle.js:156). Under count mode a nectar is worth 1, not 1.75.
   - hivecycle.js:53 and :57 label 8 as "SOURCED user". The user fact is not in the manual (hivetip_model.js:9-13). Consistent with the file's own ledger, but it reads as official.
   - hivetip_model.test.mjs:68-83 only checks that the SOURCE block contains the strings "SOURCED" and "ASSUMED". The "SOURCED" hit comes from the AndyMark-attributed line (:60). This test cannot detect a missing INFERRED tag on the 1.75 value.

5. Stale comments (contradict the current 1.75 value):
   - hivetip_mixed.test.mjs:6 says "nectar weight = 0.091 / 0.055 (SOURCED mass ratio) used as the tip weight". The value is 1.75.
   - hivetip_mixed.test.mjs:18 says `NECTAR_TO_TIP = ceil(8/1.6545)`. The value is the same number, but the comment names the wrong weight.
   - hivetip_mixed.test.mjs:12 imports `nectarToTip` from the model. The test header is out of date.

6. Starting nectar (not counted) vs physical preloads (may be counted):
   - hivecycle.js:97-98 stores 3 starting nectar with `counts=false`. This is a DECIDED ASSUMPTION.
   - Separately, scene.json has 8 `nectar_red` and 8 `nectar_blue` start balls. balls.js:258-261 gives start balls `sleeping=true`. `_hiveCapture` returns early for sleeping balls (balls.js:758). A start ball can only be captured after it is woken and rests inside a cell (balls.js:767). Its capture then goes through onCapture and is counted (app.js:434, counts=true if in the up cell).
   - Not verified: whether any scene start ball sits inside a hive cell. If one does and gets woken, it can add a counted nectar that the 3-starting-nectar rule excludes. Needs a runtime check, not a reading.
   - Also unresolved: starting nectar is 3 (hivecycle.js:58, manual 10.3.1.B) vs 5 (hivetip_model.js:52, research_manual.md). Not resolved here.

## Recommendations (no edits made)
- Make app.js:434 pass `ball.kind` (fall back to regex only when kind is missing), so it matches balls.js:121.
- Add an INFERRED tag to the SOURCE block for nectarWeight, and fix the AndyMark attribution at hivetip_model.js:60.
- Add a test that pins `HIVE_TIP.nectarWeight` as INFERRED (or a snapshot) and update the stale header at hivetip_mixed.test.mjs:6.
- Decide whether balls landing in the new up cell during the swing should count (design call).
- Decide whether `tipReady` should take the live hive rule, or be removed if it stays unused.
