## Scoring volumes (scene.json constants.flowers)
- Bbox xy and z: flower 1 x 46.622-50.593, y 138.100-142.042, z 4.254-21.054. Flowers 2-4 are analogous, with the opening centres at about 2.6 in from each wall.
- inVolume (flowerarm.js) tests x and y against the bbox expanded by margin 1.5. It tests z only as `b.z >= 0 && b.z <= zr[1] + b.r`. The lower bound zr[0] (4.254) is NOT applied.

## Findings
1. Reachability: after trimming, the stack balls are not blocked by the plate. Surface clearance is about 0.24 in per flower. The front side is open, so the robot intake can approach the stack.
2. inVolume captures all 16 start stack balls. Margin 1.5 is not what makes this work: the balls are on the opening axis and well inside the bbox.
3. Stale-data caveat: scoring_volume_bbox is 1.958-5.9 in the xy plane, and the plate reaches 2.33 (flower 2). The 0.37 in overlap with the scoring bbox is a design choice that is not documented in the code. It is not a bug in this audit.
4. Observation (not changed): inVolume ignores the z floor, so the layer-1 ball (z 1.40) is treated as scoreable/feedable even though the scoring z floor is 4.254. The feed picks the highest z ball first, so this only matters when a flower's upper layers are empty.
