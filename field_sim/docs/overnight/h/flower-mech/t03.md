# t03 FlowerArm state machine audit

Scope: `web/js/flowerarm.js` (class `FlowerArm`, plus `feedFromFlower` as it reads `fedCount`). Read only. No source edits.
Probes ran in the scratchpad (`t03_probe.mjs`, `t03_feed.mjs`) via `node` importing the real module. Nothing committed.

## Findings (ranked)

### F1 Medium: re-deploy during stowing resets fedCount, so the per-deploy feed cap is bypassed
- Where: `deploy()` line 40 (`this.fedCount = 0`), gate at `feedFromFlower` line 110.
- Repro (ran): cycles of `deploy()`, 30 feed ticks at 0.02s, `stow()`, `update(0.1)` (partial stow), repeated 6 times. Result: 10 balls released with `maxBallsPerDeploy` = 4. Baseline single continuous deploy releases exactly 4.
- Effect: the 4-ball cap is not enforced across rapid toggling. Hopper cap still holds (line 110 checks `hopper.count + pending`).
- Fix options (not applied, not my file to edit): count only on full stow (reset fedCount in the `stowed` transition), or keep the cap per physical cycle. Decision needed from lead.

### F2 Medium: `reset()` bypasses `_set`, so onState listeners are not notified
- Where: `reset()` lines 28-31 writes `this.state` directly.
- Repro (ran): listener count is 2 after deploy+update(10); `reset()` sets state to `stowed` and the count stays 2. No `deployed>stowed` event.
- Effect: any UI or servo mirror bound to onState keeps showing "deployed" after reset.
- Fix: call `_set('stowed')` in reset (or document that reset is silent).

### F3 Low: negative or unclamped dt drives progress outside [0,1]
- Where: `update()` lines 53 and 56 clamp only the upper (`Math.min(1, ...)`) for deploying and only the lower (`Math.max(0, ...)`) for stowing.
- Repro (ran): `deploy(); update(0.1); update(-1)` gives progress -2.000 while state stays `deploying`. `deploy(); update(10); stow(); update(-1)` gives progress 3.222 while state stays `stowing`. The angle clamps via `ease`, so the arm shows the deployed angle while it is supposed to be stowing, and it takes extra time to finish.
- Fix: `dt = Math.max(0, dt)` at the top of `update`, or clamp both ends.
- Severity Low only if the caller never passes negative dt. Unverified whether the 3D loop can produce one (it uses wall-clock deltas; not checked).

### F4 Low: `tipRobot()` uses a stale `angleDeg` until `update()` runs
- Where: `tipRobot()` line 66 reads `this.angleDeg`, which is only refreshed at `update()` line 59.
- Repro (ran): after `deploy(); update(0.2)` then `update(0.2)`, `tipRobot()[2]` is 11.184 before the second update and 1.962 after.
- Effect: a caller that calls `findFlowerContact` or `tipWorld` right after `deploy()`/`stow()` without an update gets the previous frame's tip. Fine if the sim always calls `update` first. Check the call order in the caller.

### F5 Low: a throwing onState listener aborts the rest of the update
- Where: `_set` line 33 runs callbacks in a loop; `update()` line 54/57 calls `_set` before `this.angleDeg = this._angle()` (line 59).
- Repro (ran): listener throws on `deploy()`. The state is already `deploying` and progress is 0, which is consistent. The remaining listeners are skipped, and on a throw from `update()` the `angleDeg` refresh at line 59 is skipped.
- Fix: try/catch per callback, or refresh angle before `_set`.

## Checked, no defect found
- Mid-motion reversal, stow->deploy and deploy->stow: progress is continuous. Stow at progress 0.444 with dt 0 stays at 0.444, then 0.1s gives 0.222. No snap (P1a). Direction reverses from the current progress.
- Progress continuity on re-deploy: `deploy()` keeps the current progress (only `fedCount` and `feedT` reset). Verified by F1 probe (progress 0.778 after re-deploy from 0.222 stow).
- Angle endpoints: progress 0 gives 90 deg, progress 1 gives -35 deg, exact. Smoothstep `ease` is clamped and monotone.
- Callbacks fire once per real transition: `stowed>deploying | deploying>deployed | deployed>stowing | stowing>stowed`. Duplicate `deploy()`/`stow()` calls are no-ops (P6).
- dt = 0 is a no-op (P7). Huge dt (10s) lands exactly at progress 1 or 0 with a single transition callback.
- Re-entrant `stow()` inside a `deployed` callback is safe (P9). The state ends `stowing`, progress 1.0.
- Huge dt in `feedFromFlower` (read only, not run): the `while` loop exits via the `fedCount >= cap` or no-top `break`, so it is bounded.
