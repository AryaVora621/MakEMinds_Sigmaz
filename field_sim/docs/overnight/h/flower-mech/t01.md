# t01: VEX Push Back matchloader research and flower_arm defaults review

Lead: flower-mech. Worker: Haiku t01. Read/research only. No files edited except this report.

## Scope note
Push Back is the VEX V5RC 2025-26 game. The sim is FTC BIOBUZZ 2026-27. The matchloader is a VEX concept, so transfer to the FTC sim is loose. Treat all numbers below as VEX reference, not FTC rules.

## Fetched and verified (what I actually read)
1. VUG3 (Different availability of Loaders): https://events.vex.com/storage/game_manual/VEX_V5_Robotics_Competition_2025-2026_Push_Back/rules/VUG3.html
   - "Drive Team Members may add Match Load Blocks to the Loaders adjacent to their Alliance Station" during Autonomous and Driver Controlled Period.
2. SG9 (Loader rules and figures): https://events.vex.com/storage/game_manual/VEX_V5_Robotics_Competition_2025-2026_Push_Back/rules/SG9.html
   - A Block can be added to a Loader only if no Block is partially or entirely within the orange portion of the Loader.
   - "Match Load Blocks may only be removed from a Loader by a Robot, and only through the bottom opening of the Loader."
   - Page gives NO Loader dimensions. The orange portion is described only by location.
3. Q&A 3019 (Oct 2025, blocks thrown into loader): https://events.vex.com/V5RC/2025-2026/QA/3019
   - "The rules do not specify exactly how a Block has to be added to a Loader." Excessive force is a violation only if the Loader is damaged.
4. Q&A 2840 (Aug 2025, drive team adds blocks to a loader touching the robot): https://events.vex.com/V5RC/2025-2026/QA/2840
   - Legal: "Drive Team Members to introduce Match Load Blocks to a Loader that is in contact with a Robot."
5. Q&A 2750 (Jan 2026, PVC pipe to load 6 balls): https://events.vex.com/V5RC/2025-2026/QA/2750
   - Using PVC pipe to help Match Loads is "additional materials... specifically disallowed by clause Aiii of rule GG1." So loader aids cannot be the design.

## flower_arm.json / flowerarm.js defaults vs. the evidence
Math checked by hand from flowerarm.js tipRobot() (paddle drop = 3.2 + 0.25 - 0.4 = 3.05 in):
- Stowed tip z = 9.2 + 8.2 - 3.05 = 14.35 in. Arm top z = 17.4 in.
- Deployed (-35 deg) tip x = 8.0 + 8.2*cos(-35) = 14.72 in; tip z = 9.2 + 8.2*sin(-35) - 3.05 = 1.45 in.

Items that look unrealistic or unverified:
- hinge {x 8.0, z 9.2}: placeholder, no source. Hinge height sets whether the paddle clears the loader lip. Unverified.
- arm.length 8.2 in: placeholder. Combined with the hinge it sets the 18 in envelope claim (stowed arm top 17.4 in). The 18 in envelope is UNVERIFIED here (kb page 403).
- deployedDeg -35: placeholder. Loader orientation and opening height are unknown, so -35 cannot be checked. Deployed tip at z 1.45 in is only plausible if the loader opening is near the floor. Unverified.
- Paddle as a hanging plate (width 8, height 3.2): placeholder. The verified rules say Blocks leave only through the bottom opening (SG9). A top-down paddle that pushes the top ball first conflicts with that bottom-exit rule. This is the strongest realism concern.
- Feed order: feedFromFlower() removes the highest ball first (top = max z). Verified loader rule implies bottom-exit, so top-first removal is not supported by any source I read. Note the sim models a flower (scoring structure), not a VEX loader, so the mismatch may be intended.
- Timing deployS/stowS 0.45 s and feedIntervalS 0.25 s: no source. Unverified.
- intakeMouth {x 10.5, z 3, halfY 8.5}: placeholder. Mouth width 17 in is large against an 8 in paddle. Unverified.
- maxBallsPerDeploy 4: matches the official hold limit of 4 in the sim rules, not a loader spec.

## Recommendations (for the flower-mech lead, not applied)
1. Model feed as bottom-opening exit (per SG9), or label the flower feed as an FTC-sim abstraction.
2. Keep all geometry values marked placeholder until measured on the Onshape CAD (json cad_todo already lists this).
3. Do not add PVC-style guides or loader aids (GG1 Aiii, Q&A 2750).
