## Mismatches: field_sim/web/data/flower_arm.json and web/js/flowerarm.js vs Java

1. Angle frame. Sim uses arm angle: stowed 90, deployed -35 (span 125 deg), flower_arm.json:9. Java uses servo travel: 0 to 120 (span 120), FlowerMech.java:26-29. No mapping exists. CAD TODO item 2 in flower_arm.json:22 names this exact mapping as still open.
2. Timing. JSON says deployS/stowS 0.45 with provenance "repo" (flower_arm.json:10). No 0.45 value exists in Java FlowerMech or FlowerMechLogic. Java implied move time is about 0.40 s (slew-derived). The "repo" label is not supported by any Java constant. Mark as mismatch or unverified.
3. Dwell. Java holds for 500 ms at deploy (FlowerMech.java:32). Sim has no dwell state: flowerarm.js:28-61 goes deploying -> deployed and stays until stow() is called. Sim needs a dwell state, or an auto-stow after dwell.
4. Stow trigger. Java auto-stows after dwell. Sim requires an explicit stow().
5. Feed block (feed.*: feedIntervalS 0.25, maxBallsPerDeploy 4, alignTol, flightS, pendingTimeout). Provenance says "repo" for maxBallsPerDeploy (flower_arm.json:17). Java has no such constant. Mark as unverified and not sourced from Java.
6. Servo count 2 Axon: matches (flower_arm.json:19 vs FlowerMech.java:19, :58).
7. Servo names: not in JSON. Sim does not need them. Java names are placeholders.
8. Fault and sync: Java has sync tolerance 10 deg and fault logic. Sim has none. Not required for sim geometry, but note it for hardware fidelity.
9. Hinge/arm/paddle/reach: Java has no values. Keep as placeholder in JSON. Provenance "placeholder" is correct.

## Pedro 2.1.0 and auto sequencing

- No Java auto references FlowerMech. Grep for flower in commands/autonomous found no files.
- Pedro autos use polling loops, not callbacks: `followPath(chain, true, timeoutS)` then `while (opModeIsActive() && robot.auto.isBusyOrTimeout())`. ShootWhileDrivingDemoAuto.java:60-61; ProfileDemoAuto.java:82-84; AutoDrivebase.java:92, :178.
- grep for addCallback/Callback in commands/autonomous found no callback usage. Java autos do not use chain callbacks. Consistent with the fact that Pedro 2.1.0 chain callbacks never fire.
- Command-group classes (SequentialCommandGroup etc.) are not used in autonomous (grep returned none).
- Implication: a flower step in auto would have to be written as a polled step in the same loop, e.g. call robot.flower.deploy(), then loop while flower.isBusy() calling robot.flower.update() and robot.auto.isBusyOrTimeout(). Robot.update() calls flower.update() at Robot.java:211; I did not verify that this runs during auto loops (unverified).
