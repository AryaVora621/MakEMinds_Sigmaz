# t20 - Headless browser check of the flower arm in the 3D sim

Lead: flower-mech. Worker: Haiku, t20. Result: flower deploy works in the browser; 4 pollen moved from the flower into the robot hopper.

## What I ran (actually executed)
- Own static server: `.venv\Scripts\python.exe -m http.server 8831 --bind 127.0.0.1 --directory web` (PID 18572). Stopped after the run; port 8831 confirmed free. No other server touched.
- Headless Chrome (version not checked) at `C:\Program Files\Google\Chrome\Application\chrome.exe` (`--headless=new`, SwiftShader, own profile in the scratchpad, remote debugging on 8832). Driver: `scratchpad/t20/drive.mjs` (Node CDP client). Chrome was closed after the run.
- Page `http://localhost:8831/index.html`; waited until `window.__sim.flowerArm` existed (ready on first poll after load).
- Flower target: `red_side` flower, id 3, `opening_center` [3.929, 48.607, 21.404] from `web/data/scene.json` `constants.flowers`.
- Pose set via `__sim.S`: x = 18.929, y = 48.607, h = PI (robot faces -x toward the flower). Camera moved to an orbit view on the flower.
- Then `__sim.flowerArm.deploy()` and 240 calls of `__sim.step(1/60)`, logging every 40 steps.

Trace (every 40 steps): step 40 state deployed, ammo 0, fed 1; step 80 ammo 3, fed 4; step 120 onward ammo 4, fed 4, nothing left within 12 in.

Note on timing: `frameBody()` in `web/js/app.js` also calls `simUpdate(dt)` from requestAnimationFrame, so my 240 manual steps ran alongside the live loop. The arm reached "deployed" within the first 40 manual steps, which is faster than the 0.45 s deploy time would need in step-count terms, so the timing numbers here are approximate and not a clean deterministic step count.
