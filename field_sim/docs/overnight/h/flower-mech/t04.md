## Drop formula vs paddle geometry (flowerarm3d.js, wrist-local z)
- Paddle box: z in [-2.800, 0.400] (center -1.2, height 3.2).
- Rubber lip: z in [-3.050, -2.800] (center -2.925, height 0.25).
- Lowest point = rubber bottom at -3.050 below the wrist.
- Code: drop = height + rubber - 0.4 = 3.050. Matches the rubber bottom exactly.
- Mismatch (doc only): flowerarm.js line 3 and json "tip = bottom edge of the paddle" reads as the paddle box bottom (2.800), but the code uses the rubber bottom (3.050). Behaviour is the rubber bottom; the comment should say so. Not a numeric bug.
- Fragility: the "-0.4" is a hard-coded copy of the 3D paddle offset (+0.4 in flowerarm3d.js lines 58-61). If the 3D offset changes, the sim contact tip drifts silently. Suggest a shared constant (proposal only, not edited).
- 3D chain check: for front and rear at -35, 0, 90 the matrix chain gives the same tip as tipRobot to 3 decimals (table above). Paddle world direction stays (0,0,-1) at every angle, so it hangs straight down as claimed.

## Heading / tipWorld
- tipWorld uses x' = x + c*lx - s*ly, y' = y + s*lx + c*ly (CCW about z, robot +x forward, +y left).
- Sim convention: app.js sets robot.position = (S.x, S.y, 0) and robot.rotation.z = S.h. Three.js Rz(h) is CCW, so the sign matches. Numeric check: |Rz(0.7) form - tipWorld| = 0.000.
- Test pose (72,72), front, a = -35, tip local (14.717, 0):
  - h = 0: (86.717, 72.000, 1.447)
  - h = +pi/2: (72.000, 86.717, 1.447) (tip moves to +y, i.e. left of robot, correct for CCW)
  - h = -pi/2: (72.000, 57.283, 1.447)
  - h = pi: (57.283, 72.000, 1.447)
- Heading sign is consistent with the sim. Pedro's own heading sign is not verified here (no Pedro file read); the bridge pose is assumed to pass h straight through (unverified).
- Rear side: tipRobot negates x (sign = -1). findFlowerContact adds PI to the bearing reference for rear, which is consistent with that mirror.

## Mismatches / notes
1. No numeric mismatch between tipRobot, tipWorld, the 3D chain, and the json. The json/default mirror matches on values; it differs only by "prov" keys (string compare false, value compare true).
2. Comment-only mismatch: "tip = paddle bottom edge" vs code using the rubber bottom (0.25 in lower).
3. Deployed reach margin is thin: 0.447 in above minTipZ at -35. A -39 deploy (or a servo overshoot) silently breaks contact.
4. Stowed height: wrist boss top 17.900, paddleTop max 17.950, vs ROBOT Z_ROBOT 18. Margin 0.05 in, and this 18 is the sim constant, not a sourced FTC rule (unverified).
5. Heading: consistent for the sim. Pedro-bridge heading sign unverified.
