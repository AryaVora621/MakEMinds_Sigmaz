# a05: parseHiveCollider and TriMesh audit (web/js/hivemesh.js lines 1-200)

Scope: read-only audit. No files edited except this report. No git write commands run.

## What I ran (vs only read)
- Ran: node probe scripts in the scratchpad (a05_probe.mjs, a05_probe2.mjs) that import web/js/hivemesh.js directly. Results quoted below.
- Read: web/js/hivemesh.js:1-200, web/js/balls.js:220-234, 700-770, tools_js/extract_hive_mesh.mjs:8-79, docs/overnight/h/hive-physics/t07.md:37.

## Verified bugs (ranked)

1. **One bad index poisons the whole mesh (silent loss of all collisions for that hive).** Verified by run.
   - hivemesh.js:75-76 folds triangle bounds into `mn`/`mx` with Math.min/max. A triangle with an index >= nv reads `undefined` from `v`, so `mn`/`mx` become NaN and stay NaN.
   - Run: a 2-triangle mesh with one triangle indexing vertex 9 gives `min = [NaN,NaN,NaN]` and `sphereContacts` returns 0 for a point that touches the good triangle (a clean mesh returns 1).
   - Patch: validate in parseHiveCollider and in the constructor:
     ```js
     for (let i = 0; i < tris.length; i++) if (!(tris[i] < nv)) throw new Error(`hive collider ${name}: tri index ${tris[i]} >= ${nv}`);
     ```
     (In the constructor, add the same check on `tris` before the loop at line 67.)

2. **Parser has no bounds checks; truncated files load silently.** Verified by run.
   - hivemesh.js:16-27. `buf.slice(o, o+nv*12)` and `buf.slice(o, o+nt*12)` clamp silently at end of buffer. `getUint8` at lines 17 and 22 throws a raw RangeError on short input.
   - Run: a header declaring 100000 verts with 48 bytes of data returns `verts.length/3 === 4` with no error.
   - Patch (after line 25):
     ```js
     if (nv > 1e7 || nt > 1e7) throw new Error('hive collider: implausible counts');
     if (o + nv * 12 + nt * 12 > buf.byteLength) throw new Error('hive collider: truncated at hive ' + name);
     ```
     Also guard `if (buf.byteLength < 8) throw ...` before line 17.

3. **NaN contacts from degenerate triangles (repeated vertex).** Verified by run.
   - closestPtTri divides by zero when a==b: line 43 `v = d1/(d1-d3)` is 0/0, and similarly line 48 (a==c), line 51 (b==c), and line 54 `den = 1/(va+vb+vc)` for zero-area triangles.
   - Run: triangle [0,0,0],[0,0,0],[1,0,0] with sphere (0.5,0.5,0.3) r=1.4 gives `depth NaN`, `point NaN`, and `sphereVsMesh` returns `hit:true, normal:[0,0,0]`.
   - Cause of NaN passing the test: hivemesh.js:125 `if (d2 >= r2) continue;` is false for NaN, so the NaN contact is kept.
   - Patch line 125: `if (!(d2 < r2)) continue;`. Also skip zero-area triangles at build time (`if (l < 1e-12) { mark }`) so they never enter the grid.
   - Production exposure: LATENT. tools_js/extract_hive_mesh.mjs:58 removes degenerate and zero-area triangles, so shipped data should not hit this. Unverified for buildFallbackMesh output (hivemesh.js >200, not read).

4. **Stamp counter overflows (dedupe silently stops after ~2.1e9 queries).** Reasoned from code, not run to completion.
   - hivemesh.js:102, 116, 163: `++this.stampN` stored into an Int32Array `stamp`. Past 2147483647 the stored value wraps negative and `st[i] === sid` never matches.
   - Effect: duplicate triangle visits in sphereContacts (max>1) and extra work in sweepSegment. Results mostly unchanged for max=1, which is what balls.js uses.
   - Rate: balls.js:725 and 751 run per ball per substep. At ~1e6 calls/s this is roughly 35 minutes of sim time, so it is reachable in a long session.
   - Patch: `if (++this.stampN >= 0x7ffffff0) { this.stamp.fill(0); this.stampN = 1; }` in both methods (and use `const sid = this.stampN;` after the check).

5. **sphereVsMesh `prev` orientation is effectively dead for penetrating centres.** Reasoned from code (line 147 and 148).
   - hivemesh.js:147 only applies `prev` when `hypot(center - contactPoint) < 1e-7`, i.e. the centre sits on the face. A centre that has passed through a thin wall by more than 1e-7 gets a normal pointing forward, so the push-out goes through the wall.
   - Production exposure: LOW. balls.js never calls sphereVsMesh (grep: only the definition at hivemesh.js:142). balls.js:725-729 handles tunnelling through sweepSegment first.
   - Patch if sphereVsMesh is ever used: replace line 147 with `if (prev) { const ex = prev[0]-o[4], ey = prev[1]-o[5], ez = prev[2]-o[6]; if (nx*ex+ny*ey+nz*ez < 0) { nx=-nx; ny=-ny; nz=-nz; } }`. This changes behaviour for penetrating centres, so keep it out of production until a test covers it.

## Checked and correct
- Ericson closestPtTri (lines 34-56): region order, vertex/edge/face tests and barycentric formulas match Ericson, Real-Time Collision Detection ch. 5.1.5 for non-degenerate triangles.
- Normals: double-sided. sphereContacts (lines 126-128) takes the normal from the closest point toward the centre, so winding does not matter. sweepSegment (line 186) flips the normal to face p0. Both are correct for thin walls.
- sweepSegment Möller-Trumbore (lines 170-179): cross products, barycentric u/w and t are correct. Degenerate triangles are skipped by the det test (line 174), so this path does not produce NaN.
- Grid: n per axis (line 81), cell index (lines 86-87), clamping (lines 112-114, 159-161). An empty mesh sets n=[1,1,1] (line 79). No O(n_tris) work per query: both queries walk only the cells the sphere or segment overlaps (lines 118-120, 165-167). Per-hive tri count is about 13624 (docs/overnight/h/hive-physics/t07.md:37).
- Transform: TriMesh has no transform. The mesh is built once per hive in local frame (balls.js:228-230) and the caller maps query points and normals with the rotation about +x (balls.js:716-717, 740). The normal rotation at balls.js:732 and 754 uses the same matrix as _toWorld, so the sign is consistent. Not rebuilt per tip.
- Name decode (line 22) skips NUL bytes instead of stopping at the first NUL. Harmless for 'red'/'blue' but wrong for a name with an embedded NUL. Nit only.
- The contacts array is capped at 8 by _tmp (line 103, 7*8 floats). Passing max > 8 writes past the end and drops silently. Callers pass 1 or the default 4, so no current bug.
