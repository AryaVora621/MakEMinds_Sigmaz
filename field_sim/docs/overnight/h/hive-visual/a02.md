# a02: HiveDynamics tip physics and timing audit

Scope: read-only audit. Only this file was written. No git write commands were run.

## What the code does (file:line)

- Tip threshold: `HIVE_PARAMS.ballsToTip = HIVE_TIP.threshold / pollenWeight` = 8 (web/js/hivecycle.js:53), `tipWeightThreshold` = 8 (:57), `animationDuration` = 0.6 s (:60), `maxAngleDeg` = 30 (:61).
- Nectar weight 1.75 is INFERRED, not measured (web/js/hivetip_model.js:20, :72).
- Starting nectar (3) is stored with `counts=false`, so it never contributes to a tip (hivecycle.js:98, header :36-38).
- Trigger: `addScoredBall` counts a ball only if the hive is at rest and the cell is the up cell (hivecycle.js:179-189). When the weight reaches 8, `_startAnim(to, true)` runs (:186-187).
- Tip-weight check: `_upCounts()` (:138) feeds `modelShouldTip` (hivetip_model.js:94-96, `>= threshold - 1e-9`).
- Motion: `_startAnim` stores `from = theta`, `to = stable[target]` (hivecycle.js:202-205). `step(dt)` advances `a.t` by dt, clamps to 0.6 s, and uses smoothstep `e = u*u*(3-2u)` for `theta = from + (to-from)*e` (:224-233).
- Settle: `_settleAt` snaps `theta` exactly to the stable angle, sets `moving=false`, and clears `counts` on all balls (:207-222). This makes the new up cell empty.
- Frame loop: app.js:1061 calls `hiveDyn[a].step(dt)` once per frame and reads `angleDeg` (theta when moving, else the stable angle).

## Damper and bounce

- No damper, spring, bounce, or overshoot is modelled. grep for damp/bounce/spring/overshoot in web/js finds nothing in hivecycle.js. The only "damper" is a comment at hivecycle.js:16, which describes the real hive and is not code. The OrbitControls damping at app.js:82 is camera only.
- The motion is a kinematic smoothstep that always ends exactly at the target. It is not dynamic.

## Measured numbers (run: node, dt = 1/60, 120 frames, script at scratchpad a02_tip.mjs)

- Trigger: 8th pollen at t = 0. `moving=true`, from -0.524 rad to +0.524 rad (-30 deg to +30 deg).
- Time to 90% of swing (first frame >= 24 deg): 0.4833 s.
- Time to settle (first frame with `moving=false`): frame 36, t = 0.6000 s.
- Max overshoot: 0.000000 deg past +30 and 0.000000 deg past -30.
- Non-monotone steps: 0. The curve is monotone with no bounce.
- Peak sampled angular speed: 149.85 deg/s, at mid-swing (smoothstep peak is 1.5 x 60 / 0.6 = 150 deg/s).
- Sampled curve (t s, deg): 0.00 -30.000; 0.100 -25.556; 0.200 -14.444; 0.300 0.000; 0.400 14.444; 0.500 25.556; 0.600 30.000; then flat at 30.000.
- Stall short of full angle: not reproducible. After 120 frames the state was `far_up`, angle exactly 30, `moving=false`, `tips=1`. A single `step(5)` also snaps to 30 with `moving=false`.

## Threshold and mix checks (same script)

- 7 pollen: progress 0.875, no tip. 8 pollen: tip.
- 4 pollen + 2 nectar (7.5): no tip, progress 0.9375.
- 4 pollen + 3 nectar (9.25): tip.
- 4 nectar (7.0): no tip, progress 0.875. 5 nectar (8.75): tip.

## Behaviour findings

- Trigger to settled is 0.60 s exactly, plus up to one frame of latency. The 90% point is at 0.48 s.
- Balls that arrive during motion are stored with `counts=false` (hivecycle.js:180) and are cleared again at settle (:213). The test "0.2 s mid-motion, then 8 more pollen" leaves 0 counted balls in the new up cell after settle. So balls launched while the hive is moving do not count toward the next tip. This is intended by the header (:39-40) but is a gameplay consequence to keep in mind. Mid-motion total stored was 19 = 3 nectar + 16 pollen.
- `setState(name, true)` uses the same animation with no tip count (hivecycle.js:236-241).
- `releaseOnTip` defaults to false, so balls stay in the cell that becomes the down cell.

## Unverified / not modelled

- Real hive tip time, overshoot, and bounce are not measured. The 0.6 s duration is a cosmetic constant (hivecycle.js:60), not a measured value.
- Nectar weight 1.75 is INFERRED (hivetip_model.js:20). Mixed-load additivity is ASSUMED (hivetip_model.js:39-42).
- Whether the real hive has a damper that lands the tip with a bounce is not in the manual. Only hivecycle.js:16 mentions a damper.
- Stall risk depends on the caller calling `step` with dt > 0 every frame. Not checked beyond app.js:1061.

## Follow-ups for other owners (not edited)

- If the real hive bounces, a second-order or damped model would need measured constants. Mark them TODO until measured.
