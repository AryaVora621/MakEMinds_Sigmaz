# a16: Hive mesh materials, visibility, render order (read-only audit)

Scope: web/js/app.js 100-260 plus grep for visible/transparent/opacity/layers. Also read web/data/scene.json and scene.bin (alpha values). Nothing was run or rendered; no screenshot was taken.

## Answers

**1. Can balls inside a cell be seen? Partly. The hive shell is not fully opaque.**
- Hive skin panels are transparent. Hive Goal Back Skin (part p027), Bottom Skin (p028) and Top Skin (p030) are stored only in the `trans` slot. Their vertex alpha is 51/255 = 0.20 for every vertex (read from web/data/scene.bin, `parts.p027.trans.col`). They render through `matTrans`, which is transparent, has `depthWrite:false` and alpha 0.2 (app.js:128). Balls behind these panels should be visible.
- The basket and rib structure is opaque (for example "am-1589 Basket End Skin", "am-5868 Basket Base Tube", "Rib"). It uses `matOpaque` (app.js:127) and is drawn solid. Any opaque basket wall between a ball and the camera hides that ball.
- Which of these walls is "near" depends on the camera and the tip state. This was inferred from the material split. It is UNVERIFIED until a screenshot is taken.

**2. Are ball meshes parented to the field while the hive group rotates? Yes, they are parented to neither, and that is correct.**
- Balls go into `ballGroup`, which is added directly to `scene` (app.js:297). `syncBallMeshes()` writes world positions `b.x, b.y, b.z` (app.js:302-311).
- The hive group is rotated in `simUpdate` (app.js:1062: `h.group.rotation.x = rad(h.shown - h.angles[h.cad])`). Only the hive meshes rotate. Balls do not.
- This matches the physics: `world.setHiveAngles` (app.js:451) passes the same tip angle to BallWorld, and balls are simulated in world space. The visuals are consistent with the physics.
- Hive instance matrices are premultiplied by a translation of `-pivot` (app.js:161) and the group sits at `pivot` (app.js:140). That makes the rotation pivot the hive centre, so the rotation is correct.

**3. Is there a way to make the near wall transparent or add a cutaway? Yes, in three ways.**
- (a) Existing: the layer checkbox "Red hive" or "Blue hive" (app.js:502) hides the whole hive mesh, including the skins and the basket. This is a full hide, not a cutaway. Keyboard `l` only toggles labels (app.js:596).
- (b) Ghost the opaque hive walls: route opaque hive parts through a transparent material and give them their own layer, so they can be toggled.
- (c) Clipping plane: a true cutaway for the near half.

## Suggested patches (not applied; owner of app.js must apply)

Patch A, ghost the basket walls (app.js ~127 and ~166-171):
```js
// after line 128
const matHiveGhost = new THREE.MeshStandardMaterial({ vertexColors: true, roughness: 0.3, metalness: 0, side: THREE.DoubleSide, transparent: true, opacity: 0.25, depthWrite: false });
```
In the loop at app.js:158, for `b.parent !== 'field' && label === 'opaque'`, use `matHiveGhost` and add the mesh to `addLayer('hive_ghost', im)` instead of `addLayer(key, im)`. Add `['hive_ghost', 'Hive walls (ghost)']` to `defs` at app.js:502. Set its checkbox default to on, which is a user choice (ASSUMED).

Patch B, clipping cutaway (a true cutaway):
```js
// near line 127, once
renderer.localClippingEnabled = true;
const hiveClip = { red: new THREE.Plane(new THREE.Vector3(0, 0, -1), 0), blue: new THREE.Plane(new THREE.Vector3(0, 0, -1), 0) };
matOpaque.clippingPlanes = []; // set per hive below
```
Clipping planes are in world space, so they must be updated every frame in `simUpdate` near app.js:1062. Use `hiveClip[a].constant = <world Y of the near edge>`, computed from `hive[a].pivot` plus the cut offset. The cut offset is a design choice (TODO). Do not hard-code a value; take it from the CAD bounds in scene.json `groups.hive_<a>`.
Caveat: `matOpaque` is shared by the field and robot, so clip a separate hive-only material clone.

Patch C, skins ghost slider: expose `matTrans.opacity` (currently implicit 0.2 from vertex alpha; `material.opacity` multiplies vertex alpha) as a slider to tune the skins. Note that `matTrans` is shared by all trans parts (field tape, perimeter glass, flower volume), so use a separate hive material if only the hive should change.

## Other notes for the owners
- app.js:166 sets `castShadow` on opaque hive parts. Basket walls therefore cast shadows onto balls inside the cell. This is correct but makes the hidden-ball problem look worse. Consider `castShadow=false` for the ghosted walls.
- app.js:170 hides the CAD static balls (`scoring_*`). This is correct; physics balls replace them.
- Render order: transparent skins use `depthWrite:false` and are drawn after the opaque balls. Balls behind a skin draw correctly. No `renderOrder` is set on hive meshes (grep found none). This is fine for now.
- Verification needed (unverified): take a headless Chrome screenshot of a tipped hive with balls dropping through the opening, once from the audience side and once from the far side. Check whether any ball is hidden by an opaque basket wall. This audit did not do that.
- Field-level note: `p064` (Field Side Glass) is also trans at alpha 0.2, so the same glass rule applies to the perimeter wall and will affect the field view.
